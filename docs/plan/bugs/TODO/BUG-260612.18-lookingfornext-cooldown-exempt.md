# BUG-260612.18: lookingForNext reroute exempt from failure cooldown and loses a tick vs the not-weldable path

## Status: Open
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260612.1 #L2 — `NanobotSystem.Welding.cs:151-157, 211-218, 243-249, 256-269`

## Description
Two same-condition inconsistencies in the weld picker: (1) when the lock-on is dropped for grid-limit/claim-race, the `lookingForNext` reroute locks the next block but doesn't weld it this tick, while the "no longer weldable" drop continues and welds in the same tick — one path loses a tick for the same situation; (2) the failure-cooldown skip exempts `lookingForNext`, so the reroute can lock onto a block in the 15 s global starvation cooldown, then fail it next tick (lock-ons are also exempt) — a guaranteed wasted weld-slot claim and pull walk that every other BaR knows to skip.

## Root Cause
Reroute branch predates the cooldown skip and the same-tick-continue pattern.

## Fix
Apply the cooldown skip to the `lookingForNext` selection, and consider continuing (weld in the same tick) instead of breaking after reroute, mirroring the not-weldable path.
