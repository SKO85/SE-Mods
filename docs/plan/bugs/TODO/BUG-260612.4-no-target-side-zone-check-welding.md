# BUG-260612.4: Welding has no target-side safe-zone check — BaR outside a zone welds blocks inside it

## Status: Open
## Severity: High
## Version: v2.5.6
## Found In: REVIEW-260612.1 #H4 — `Handlers/SafeZoneHandler.cs:445-502`, `NanobotSystem.Scanning.Block.cs:233`

## Description
Weld permission is computed solely from the BaR's own block position (`GetIntersectingAttackerSafeZone` → `State.SafeZoneAllowsWelding`, consumed only as a welder-side gate in the scan filter). There is no per-target analogue of `IsProtectedFromGrinding` for welding, and `IncreaseMountLevel` bypasses the engine's zone checks (only `projector.Build` enforces them). A BaR parked just outside a welding-prohibited zone (or with a large area offset) repairs/welds blocks inside it — something vanilla tools cannot do. Grinding and projection-building both have target-side checks; plain repair welding is the only unprotected action.

## Root Cause
Protection model only ever gated welding on the attacker side.

## Fix
Add a target-side zone check to the weld scan filter (and ideally the weld execution gate, see BUG-260612.13): resolve the target grid's intersecting zone (the 15 s `GridIntersectingZones` cache already exists) and reject weld targets when that zone prohibits Welding for the BaR's owner.
