# BUG-260612.17: Assignment releases without owner check can delete another BaR's claim

## Status: Open
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260612.1 #L1 — `NanobotSystem.Welding.cs:274-277`, `NanobotSystem.Grinding.cs:155-173, 233`, `Handlers/BlockSystemAssigningHandler.cs:104-107`

## Description
`ReleaseFromSystem` removes the key regardless of which system owns the claim. Paths that can release someone else's claim: the weld lock-on-vanished recovery (stale lock-on whose TTL expired and was claimed by another BaR), and the ScriptControlled weld/grind paths (the `IsAssignedToOtherSystem` pre-filter is skipped when `CurrentPicked*Block != null`, so the release sites can hit a foreign claim). Inconsistent with BUG-260610.32's claim-race reasoning. Bounded impact: temporary duplicate work on one block.

## Root Cause
Release API has no owner parameter.

## Fix
Add an owner-checked overload `ReleaseFromSystem(key, systemId)` that only removes when the stored owner matches, and use it at the affected sites.
