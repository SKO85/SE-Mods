# BUG-260612.19: Lock-on block with FatBlock.Closed wastes the whole weld tick

## Status: Open
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260612.1 #L3 — `NanobotSystem.Welding.cs:167-170`

## Description
If the lock-on block's fat block is closed, the loop `continue`s without clearing the lock-on or setting `lookingForNext`. Since `lockOnFound` is already set, every remaining target is skipped by the lock-on filter and the lock-on-retry recovery doesn't fire — the tick is fully wasted. Self-heals via the caller's unconditional `State.CurrentWeldingBlock = currentWeldingBlock` (null) write; the assignment is left to TTL expiry instead of being released.

## Root Cause
Closed-fat-block skip predates the lock-on clear pattern used by the not-weldable path.

## Fix
Clear the lock-on (and release the assignment) and continue, mirroring the not-weldable drop at `Welding.cs:265-268`.
