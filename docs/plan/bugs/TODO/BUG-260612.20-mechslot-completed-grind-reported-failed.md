# BUG-260612.20: mech-slot early-exit reports a completed grind as failure — list removal and cluster propagation skipped

## Status: Open
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260612.1 #L4 — `NanobotSystem.Grinding.cs:417-446`

## Description
When a block becomes fully dismounted in this call but `TryClaimMechanicalGrindSlot()` fails, `DecreaseMountLevel` + `MoveItemsFromConstructionStockpile` have already run (real work; items in transport), yet `ServerDoGrind` returns false. The caller releases the assignment, leaves `grinding = false` (state/effects flicker), and skips both the immediate list removal and the cluster propagation — every member walks the dead entry until each hits the destroyed-skip path. Self-healing (raze enqueued next tick; transport drains) but loses a tick and the propagation benefit on exactly the expensive block class (pistons/rotors).

## Root Cause
Budget gate placed after the work it was meant to gate, with a failure-shaped return.

## Fix
When the block is fully dismounted at the mech gate, treat the grind as completed (return true with removal/propagation) and let only the raze be deferred by the mech budget.
