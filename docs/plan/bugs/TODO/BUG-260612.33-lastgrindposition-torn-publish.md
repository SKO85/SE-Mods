# BUG-260612.33: _LastGrindWorldPosition published cross-thread without synchronization — torn read possible

## Status: Open
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260612.1 #L17 — `NanobotSystem.cs:198-199`, `NanobotSystem.Grinding.cs:186-187`

## Description
`_LastGrindWorldPosition` (Vector3D, 24 bytes — not atomic) and `_HasLastGrindPosition` are written on the main thread and read by the background scan for the locality-aware grind sort, with no barrier/ordering. The scan can observe `flag = true` with a stale or torn position. Impact is benign (sort hint only — a bad hint mis-orders candidates for one scan), flagged for threading-model hygiene.

## Root Cause
Unsynchronized multi-word publish.

## Fix
Publish position then flag with the flag declared `volatile` (accepting a stale-but-untorn pair is fine for a hint), or snapshot both under the existing `_Welder` lock the scan already takes at entry.
