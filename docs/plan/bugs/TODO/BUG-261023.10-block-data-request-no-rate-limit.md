# BUG-261023.10: Block data requests have no rate limit (DoS amplification)

## Status: Open
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-261023.1 #10 — `Handlers/NetworkMessagingHandler.cs:106-129` (`ServerMsgBlockDataRequestReceived`)

## Description
Any client can request settings + full state (`GetTransmitFull`) for any BaR EntityId as often as it
likes; each request costs the server two serializations and two sends. A modified client can loop over all
EntityIds. (The read-only information exposure itself was accepted in BUG-260610.2.)

## Steps to Reproduce
Crafted client sending MSGID_BLOCK_DATAREQUEST in a loop.

## Root Cause
Rate limiting was added only to the settings message (BUG-260610.31).

## Fix
Proposed (not implemented):
Per-(sender, EntityId) minimum interval (e.g. 2 s) plus a per-sender cap (e.g. 50 requests / 10 s);
drop silently. Legit clients request once per streamed BaR.

## Scenario
SCN-NET-001

## Related
BUG-260610.2, BUG-260610.31, BUG-260824.8
