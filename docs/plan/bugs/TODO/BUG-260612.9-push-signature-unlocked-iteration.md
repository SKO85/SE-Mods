# BUG-260612.9: ComputePushTargetsSignature iterates _PossiblePushTargets without its lock

## Status: Open
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-260612.1 #M2 — `NanobotSystem.Inventory.cs:20-31, 134, 186`, `NanobotSystem.Scanning.cs:1316`

## Description
The signature computation iterates `_PossiblePushTargets` with no lock. Main-thread call sites race the background scan swap (`lock (_PossiblePushTargets) { Clear(); AddRange(); }`): a `Clear` between the `Count` check and the indexer throws `ArgumentOutOfRangeException` inside `ServerTryWeldingGrindingCollecting` (no in-method catch), and a torn read yields a wrong signature (mis-arms/mis-clears `_PushTargetsFull`; self-heals ≤15 s). The background call site (`Scanning.cs:1316`) races the main-thread clears that run before the re-entry guard. Every other consumer of this list already locks the same object.

## Root Cause
One reader outside the established lock discipline.

## Fix
Take `lock (_PossiblePushTargets)` inside `ComputePushTargetsSignature` (one line; all call sites benefit).
