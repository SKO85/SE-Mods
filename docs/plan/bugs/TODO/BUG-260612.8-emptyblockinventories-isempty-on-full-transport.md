# BUG-260612.8: EmptyBlockInventories reports isEmpty=true when it bailed on a full transport inventory — razed loot, deleted bot corpses with loot

## Status: Open
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-260612.1 #M1 — `NanobotSystem.Inventory.cs:267`, `NanobotSystem.Grinding.cs:360-453`, `NanobotSystem.Collecting.cs:118-133`

## Description
`if (remainingVolume <= 0) return true;` runs after the `srcInventory.Empty()` check (a non-empty inventory provably exists) but leaves the `isEmpty` out-param at its initialized `true`. Consumers trust it: the grind path proceeds to `DecreaseMountLevel` and razes a container with cargo still inside; the collect path `Delete()`s dead bots with loot and marks the corpse Ignore. Reachable when `_TransportInventory.CurrentVolume >= _MaxTransportVolume` at entry while `State.InventoryFull` is false (e.g. transport parked full of weld leftovers after the welder drained below 90%). Related: the `!emptying` branch also lets grinding proceed by design, compounding the unreliable "don't raze with loot" guard.

## Root Cause
Early-return path doesn't distinguish "source is empty" from "no room to empty it into".

## Fix
Set `isEmpty = false` (and return) on the transport-full bail; consumers then correctly defer the dismount/delete until transport drains.
