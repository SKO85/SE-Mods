# BUG-260612.37: Script.cs hard-crashes on servers with ScriptControllFixed

## Status: Open
## Severity: Medium
## Version: v2.5.6
## Found In: Script audit 2026-06-12 — `SKO-Nanobot-BuildAndRepair-System-Script/Script.cs` ~1488 (`ScriptControlled` getter), ~1501 (`MissingComponents()`)

## Description
When the server sets `Welder.ScriptControllFixed=true`, the mod registers none of
the scripting properties (see BUG-260612.38). Two script paths then call the
terminal API unguarded and throw on the missing property, killing the PB:
- `ScriptControlled` getter: `_Entities[0].GetValueBool("BuildAndRepair.ScriptControlled")`
  — hit every Status page refresh.
- `MissingComponents()`: per-entity `entity.GetValue<MemorySafeDictionary<...>>("BuildAndRepair.MissingComponents")`
  — hit every auto-queue cycle.

The script should degrade gracefully (show "n/a" / skip auto-queuing) instead of
crashing.

## Steps to Reproduce
1. Set `ScriptControllFixed=true` in the mod settings on a server.
2. Recompile the companion script. Auto-detect still succeeds via the
   `BuildAndRepair.Mode` fallback probe.
3. First `Handle()` tick crashes the PB in `DisplayStatus` or `CheckAssemblerQueues`.

## Root Cause
Direct `GetValueBool`/`GetValue` calls on `_Entities[...]` bypass the
exception-safe `GetValue<T>` helper; SE throws when a terminal property id is not
registered.

## Fix
Route `ScriptControlled` through the safe `GetValue<T>` helper (or try/catch) and
wrap the per-entity `MissingComponents` read in try/catch, treating a missing
property as an empty result. Related: BUG-260612.36 (same trigger, list
wrappers), BUG-260612.38 (mod-side registration nesting).
