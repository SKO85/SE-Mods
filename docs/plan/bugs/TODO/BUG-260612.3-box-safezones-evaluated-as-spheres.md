# BUG-260612.3: Box-shaped safe zones evaluated as spheres of zone.Radius — under-protection inside box zones

## Status: Open
## Severity: High
## Version: v2.5.6
## Found In: REVIEW-260612.1 #H3 — `Handlers/SafeZoneHandler.cs:377-384, 404-408, 240-242`

## Description
SE safe zones have `Shape` = Sphere or Box (box `Size` up to 500 m per axis); for a box zone `Radius` is just the stale slider value. All three geometry tests (`GridIntersects`, `BlockIntersects`, the distance precheck) build a `BoundingSphereD(zone position, zone.Radius)` and never consult `Shape`/extents. A grid inside a large box zone but more than `Radius` from its center fails the intersection test → `IsProtectedFromGrinding` returns false (cached 15 s) → BaRs grind inside an active box zone; the welder-side flags also stay permissive. Same class as the fixed BUG-260610.4 but for shape; predates that fix.

## Root Cause
Zone geometry handling assumes spherical zones.

## Fix
When `Shape == Box`, test against the zone's world AABB (`zone.PositionComp.WorldAABB`, conservative) or its OBB; the precheck can use the AABB half-diagonal in place of `Radius`.
