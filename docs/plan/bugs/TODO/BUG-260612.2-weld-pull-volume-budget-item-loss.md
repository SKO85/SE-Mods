# BUG-260612.2: Weld component pull can destroy items — volume budget ignores transport content, AddItems unchecked

## Status: Open
## Severity: High
## Version: v2.5.6
## Found In: REVIEW-260612.1 #H2 — `NanobotSystem.Welding.cs:833, 1275-1277`

## Description
`ServerFindMissingComponents` starts every pick pass with `remainingVolume = _MaxWeldTransportVolume` and never subtracts `_TransportInventory.CurrentVolume` (contrast `EmptyBlockInventories`, `Inventory.cs:245`, which does). `ServerPickFromWelder` then does `welderInventory.RemoveItems(...)` followed by `_TransportInventory.AddItems(...)` with the add result unchecked — `AddItems` adds nothing and returns false when it doesn't fit. When the transport inventory can't drain (welder block full, conveyor auto-pull keeps refilling it), repeated passes stack leftovers toward the real transport cap; once reached, the removed stack is silently deleted. Long-standing (not a fix-pass regression); this is the one verified hard item-destruction path in the flow.

## Root Cause
Per-pass logical budget treats the transport inventory as empty; no result check on the final transfer.

## Fix
Subtract `_TransportInventory.CurrentVolume` from the initial budget (mirroring `EmptyBlockInventories`), and check the `AddItems` result — on failure, return the items to the welder inventory (or skip the `RemoveItems` by doing add-first/transfer semantics).
