# BUG-261023.1: Missing-components aggregate rebuild is unbudgeted, phase-aligned and repeated by every cluster member

## Status: Open
## Severity: High
## Version: v2.5.6
## Found In: REVIEW-261023.1 #1 — `NanobotSystem.Welding.cs:1410-1519` (`ServerTryRebuildMissingComponentsAggregate`), call site `NanobotSystem.Operations.cs:66`

## Description
The BUG-260824.2 fix (GitHub #142) rebuilds `State.MissingComponents` every 3 s **per BaR** on the main
thread: `GetMissingComponents` on every non-ignored weld target (up to `MaxPossibleWeldTargets`, now 1024)
plus `GetItems` on the welder, transport and every connected source until the need is covered. It runs
outside the weld ms budget and has no cap. Three things make it spike:

1. `_NextMissingAggregateAt` starts at zero and advances from the tick it fired. BaRs in the same stagger
   group run `ServerTryWeldingGrindingCollecting` in the same frame (`cycle % effectiveGroups`), so their
   rebuilds fire in the **same frame every 3 s, forever**.
2. Cluster members each hold a near-identical copy of the coordinator's target list and each repeat the
   full walk — 5 co-located BaRs = 5x the same work, 50 BaRs = 50x.
3. With a shortage (need stays positive) the source subtraction walks every source inventory each time.

Estimate: ~2-10 µs per `GetMissingComponents` × 1024 targets ≈ 2-10 ms per BaR; 20 BaRs in one group ≈
40-200 ms in one frame every 3 s. This is new in v2.5.6 and lands exactly in the GitHub #143 scenario
(large base, many BaRs), so it must be fixed or proven cheap before release.

## Steps to Reproduce
1. Large base (1000+ damaged/projected blocks in range), 5-20 BaRs in one cluster, empty-ish cargo.
2. `/nanobars profile start 120 0` (or harness `test run S08 x5`).
3. `RebuildMissingComponentsAggregate` maxMs and its spacing; sim speed dips every 3 s.

## Root Cause
Aggregate correctness was prioritised over cost: no budget, no time slicing, no phase offset, no
sharing within a cluster.

## Fix
Proposed (not implemented):
Minimum (do all three):
- **Phase offset**: on the first call seed `_NextMissingAggregateAt = playTime + TimeSpan.FromMilliseconds((EntityId & 0x7FFFFFFF) % 3000)` so rebuilds spread across the 3 s window.
- **Time slice**: keep a cursor into the target snapshot; walk at most 128 targets per call, accumulate into
  `_AggMissingNeed`, and only publish (subtract stock, swap into `State.MissingComponents`) when the cursor
  wraps. Keep the previous published list until then (no flicker).
- **Skip when unchanged**: if `State.PossibleWeldTargets.CurrentHash` is unchanged since the last publish
  and the last result was empty, skip the walk.
Optional: cluster members with the coordinator's exact area reuse the coordinator's published aggregate.
Verify with S08: `RebuildMissingComponentsAggregate` maxMs ≤ 2, no 3 s sim-speed sawtooth. Profile key unchanged.
