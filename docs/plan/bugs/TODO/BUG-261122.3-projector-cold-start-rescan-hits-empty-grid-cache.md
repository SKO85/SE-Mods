# BUG-261122.3: Projector cold-start rescan is swallowed by the empty-grid cache

## Status: Open
## Severity: Medium
## Version: v2.5.6
## Found In: PR #151 part 2 (Lejangt), REVIEW-261122.1 #3/#4 — `NanobotSystem.Scanning.cs:100-125` (cold start), `NanobotSystem.Scanning.Block.cs:533-565` (empty-grid fast path), `:703`, `:831` (marking), `:765` (projector gate)

## Description
When the coordinator is idle, `HasBuildableProjectorOnGrid()` (projector `BuildableBlocksCount > 0`) forces
one rescan so a new projection is picked up immediately (BUG-260610.29 made it one-shot). The forced scan
then usually hits the empty-grid fast path for the projector's grid: the previous scan found no targets
(the projector was skipped while its count was 0) and wrote `_EmptyGridCache[grid]`. The fast path only
traverses connections and never looks at the projector, so the projection is ignored until the empty entry
expires (`EmptyGridRescanDelaySeconds`, default 20 s) and the idle scan comes round again. A 3 s
`GridScanCache` entry can return the same stale "nothing here".

Result: new projections start late (tens of seconds), not "never". Not a 1.211 regression.

## Root Cause
The cold-start trigger resets the idle backoff but not the caches that made the grid look empty.

## Fix (proposed)
On the cold-start transition (the one-shot branch in `UpdateSourcesAndTargetsTimer`), drop the cache state for
the projector grids that fired: remove their `_EmptyGridCache` entries and `GridScanCache.Invalidate` them
(PR #151 clears the whole `_EmptyGridCache`, which is also acceptable because it is one-shot).

Not adopted from PR #151 part 2 (see REVIEW-261122.1):
- Dropping the `BuildableBlocksCount > 0` gate: its premise ("recomputed asynchronously since 1.211") is wrong —
  1.210 already computes it in `MyProjectorUpdateWork` (IL: `UpdateProjection` → `m_updateTask.IsComplete` →
  `MyProjectorUpdateWork.Start`). Decide on data: the new `ProjectorProbe` profile line (profiling only,
  every 30 s per projector reporting 0) logs `stale=True` when the count is 0 but projected blocks CanBuild.
- Never marking grids with a working/projecting projector as empty: disables the empty-grid optimisation for
  every base with a powered projector (#143-class cost). Revisit only if the probe shows stale counts.
- Projected-grid EntityId change trigger ("tiered update system recreates preview grids"): not in the 1.211
  changelog, unverified.

## Scenario
SCN-WELD-002 (step: load a blueprint into an idle BaR's projector → first projected block built within one
scan interval, not after `EmptyGridRescanDelaySeconds`).
