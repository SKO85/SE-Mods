# BUG-260824.11: Terminal-controls init retry re-adds already-registered controls/actions

## Status: Open
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260824.1 — `Terminal.cs:606`

## Description
BUG-260610.38's exception rollback resets `CustomControlsInit` and clears only the mod-local
list; controls/actions/properties already registered via
`MyAPIGateway.TerminalControls.AddControl/AddAction` cannot be withdrawn, so the retry
re-adds every id that succeeded before the throw.

Failure: `InitializeControls` throws midway after ~40 controls and their toolbar actions were
added. Retry re-runs from the top: `Properties.cs:33/56/68` and `OnOffSwitches.cs:56-87`
unconditionally CreateProperty/CreateAction + AddControl/AddAction with no existing-id lookup,
and the SE API appends without dedup → every pre-failure control/action/property appears
twice in the terminal and toolbar-setup screens. The comment's claim that engine-side entries
are "simply re-used on the retry" has no implementing code.

## Root Cause
Rollback assumes engine-side registration is idempotent; it is append-only.

## Fix
Track a mod-side "registered ids" set that survives the rollback and skip already-added ids on
retry; or make the retry a no-op after partial success and log instead.
