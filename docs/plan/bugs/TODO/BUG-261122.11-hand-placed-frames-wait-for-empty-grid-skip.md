# BUG-261122.11: Hand-placed block frames wait up to EmptyGridRescanDelaySeconds before welding

## Status: Open
## Severity: Low
## Version: v2.5.6 (behaviour since FEAT-017, v2.5.0)
## Found In: BUG-261122.10 analysis (2026-11-22) — `NanobotSystem.Scanning.Block.cs` empty-grid fast path

## Description
A block frame placed by a player on a grid the BaR found empty (all repaired) is not welded until the empty-grid
mark expires (default 20 s) and, when idle, the next backed-off scan (10 s). Placing raises no damage event, so
BUG-261122.10's stamp does not cover it.

## Fix (proposed)
Stamp `GridChangeHandler.MarkChanged` on block add: subscribe `IMyCubeGrid.OnBlockAdded` per grid on the main
thread (OnEntityAdd + existing grids, unsubscribe on close), or compare the grid's block count against the count
stored with the empty mark (needs a whitelisted count). Projector builds are already handled (BUG-261122.3).

## Scenario
SCN-CORE-001 (new harness scenario: place a frame on an all-repaired rig, measure time to first weld).
