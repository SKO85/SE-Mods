# BUG-260824.3: NetworkMessagingHandler.Unregister keeps latch pattern BUG-260610.27 fixed elsewhere

## Status: Open
## Severity: High
## Version: v2.5.6
## Found In: REVIEW-260824.1 — `Handlers/NetworkMessagingHandler.cs:59`

## Description
`Unregister()` null-guards `MyAPIGateway.Multiplayer` / `MyAPIGateway.Utilities` BEFORE
resetting the static `_registered` flag. If either is already torn down during UnloadData
(engine-version-dependent ordering — the exact trigger BUG-260610.27 documents), the bare
return leaves `_registered = true`, so the next world's `Register()` no-ops: no settings
sync, no state sync, no chat-command transport until a full game restart.
`DamageHandler.cs:41-44` and `SafeZoneHandler.cs:142-157` were fixed for the same pattern;
this sibling was missed.

## Root Cause
Flag reset gated behind API-availability guard in a static handler that survives world reloads.

## Fix
Reset `_registered = false` (and clear any local state) unconditionally before touching the
gateway objects; only the actual unregister calls need the null guards.
