# BUG-260610.43: Grind-color tooltip claims priority list is ignored, but code requires the type to be enabled

## Status: Open
## Severity: Low
## Version: v2.5.6
## Found In: docs audit (2026-06-10) — `NanobotSystem.Scanning.Block.cs` (`AsyncAddBlockIfGrindTarget`), grind-color tooltip in `Localization/Texts*.cs`

## Description
The in-game tooltip for the grind-color feature says color-marked blocks are ground regardless of the Grind Priority list's enabled state. The code disagrees: both grind target routes (grind color AND janitor relations) check `BlockGrindPriority.GetEnabled` and skip block types that are disabled in the priority list. A player who disables e.g. "Armor" in the grind priorities and paints an armor block with the grind color expects it to be ground (per the tooltip) — it won't be.

The docs (Grinding page) were updated during the 2026-06-10 audit to describe the actual code behavior; the tooltip still carries the stale claim.

## Root Cause
Tooltip text predates (or diverged from) the unified enabled-state check in the scan filter.

## Fix
Decide the intended behavior, then align the other side:
- Option A (recommended, no behavior change): fix the tooltip text in all `Localization/Texts*.cs` languages to say color-marked blocks still respect the priority list's on/off state.
- Option B: make the grind-color route bypass `GetEnabled` to match the tooltip — a behavior change for existing worlds; only if the original intent is confirmed.
