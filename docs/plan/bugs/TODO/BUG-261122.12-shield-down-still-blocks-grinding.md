# BUG-261122.12: Enemy grid with its DefenseShields shield down is still never ground

## Status: Suspected (from DS source; harness S59 verifies)
## Severity: Medium
## Version: v2.5.6 (and released versions)
## Found In: DS source review 2026-11-22 (workshop 3154379105, API files 2025-09-10) — `NanobotSystem.State.cs` `IsShieldProtected`

## Description
`IsShieldProtected` asks DS `IsBlockProtected(block)` only. In DS that call returns true when the block lies inside
the ellipsoid of its grid's shield controller (`TAPI_IsBlockProtected`: `IdToBus` + point-in-`DetectMatrixOutsideInv`)
and never checks the shield state. DS clears the grid's controller only when the controller is suspended (not
functional, wrong owner, wrong ship/station role); a controller that is switched off, lowered or drained keeps it.
So a pirate ship with a functional but down shield is treated as shielded and the janitor never grinds it.
`ProtectedByShield` / `GridShieldOnline` do check `Online && !Lowered`.

## Steps to reproduce
`test run S59` (DefenseShields loaded): pirate ship, shield online, controller switched off -> expected ground.

## Fix (proposed, after S59 confirms)
Protected only when the shield is up: `IsBlockProtected(block) && GridShieldOnline(block.CubeGrid)`; consider
`ProtectedByShield(grid)` too, for grids sitting inside another grid's bubble (not covered by IsBlockProtected).

## Scenario
SCN-ZONE-001 (S58 shield up -> not ground; S59 shield down -> ground; S60/S61 ShieldCheckEnabled).
