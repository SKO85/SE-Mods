# BUG-260612.6: Overlapping safe zones — first intersecting zone wins, permissive zone can mask a prohibiting one

## Status: Open
## Severity: High
## Version: v2.5.6
## Found In: REVIEW-260612.1 #H6 — `Handlers/SafeZoneHandler.cs:292-343, 447-454`

## Description
`GetIntersectingSafeZone` and `GetIntersectingAttackerSafeZone` return the FIRST intersecting zone in `Zones` (ConcurrentDictionary — arbitrary enumeration order), and only that zone's action flags are evaluated; `GridIntersectingZones` then caches that single zoneId for 15 s. Vanilla semantics are "prohibited if ANY containing zone prohibits". With overlapping zones (e.g. a player's own permissive safe-zone-block bubble overlapping an admin or enemy zone), whichever enumerates first wins — nondeterministically allowing grinding/welding inside a prohibiting zone, and exploitable by deliberate zone placement.

## Root Cause
Single-zone resolution where the rule needs aggregation across all intersecting zones.

## Fix
Evaluate all intersecting zones and AND the permissions (action prohibited if any intersecting zone prohibits it). Cache the aggregated verdict (per action bitmask) instead of a single zoneId, or cache the list of intersecting zone ids.
