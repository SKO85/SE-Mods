# BUG-260612.36: Script.cs priority-list wrappers crash on null property value

## Status: Open
## Severity: Medium
## Version: v2.5.6
## Found In: Script audit 2026-06-12 — `SKO-Nanobot-BuildAndRepair-System-Script/Script.cs` ~1265, ~1326, ~1387

## Description
`WeldPriorityList()`, `GrindPriorityList()`, and `ComponentClassList()` fetch the
list via the exception-safe `GetValue<T>` helper (returns `default(T)` = null on
any failure) and then iterate it with `foreach` without a null check. A null
return kills the whole programmable block with "script execution terminated"
instead of showing an empty page.

## Steps to Reproduce
1. Run the companion script on a server with `ScriptControllFixed=true`
   (the `BuildAndRepair.WeldPriorityList` etc. properties are never registered —
   see BUG-260612.38), or against a block whose getter returns null.
2. Let a display cycle to the `BlockWeldPriority` or `BlockGrindPriority` page.
3. PB throws NullReferenceException and halts.

## Root Cause
The display methods guard the *returned* list (`if (list == null) return;`), but
the NRE happens inside the wrapper before it returns.

## Fix
Add `if (list == null) return null;` after the `GetValue` call in all three
wrappers. Also bump the script's version header (currently `v2.5.4`) when
shipping the change.
