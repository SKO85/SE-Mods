# BUG-261123.3: Grind loop re-walks already-ground entries every tick; saturation check counts them as live

## Status: Open
## Severity: Medium
## Version: v2.5.7
## Found In: REVIEW-261123.1 (profiler-driven performance review, 2026-11-23) — `NanobotSystem.Grinding.cs:74-141`, `NanobotSystem.Scanning.cs:250-262`

## Description
Each tick the grind picker re-checks entries whose block is already ground (two lookups per entry) and re-queues
the same raze. Removals only reach the BaR's own cluster, and the "list still full" saturation check counts dismounted
armor as live, so rescans are skipped for up to 60 s. Measured grind-loop overhead 0.04-0.11 ms per ground block,
about the same with 2 or 10 clusters (S66 / S67 / S70) — hypothesis to confirm with one `detail` run (skip counters).

## Fix (proposed)
Flag dead entries once (Ignore + gone) and skip them before any lookup; count only live entries in the saturation
check so a rescan is not suppressed. Expected 50-80 % of the grind-loop overhead (~1-5 ms/s in S66 / S67 / S70).

## Scenario
SCN-GRIND-002 / SCN-BUDGET-008 — ingame:S66, S67, S70 (grind-loop ms/s, rescan cadence), S04 / S95 unchanged.
