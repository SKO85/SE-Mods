# BUG-260824.6: SharedEntityCache verifies only 50 m-quantized keys — different-size scan boxes share results

## Status: Open
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-260824.1 — `Caches/SharedEntityCache.cs:53`

## Description
The BUG-260610.8 collision fix verifies only quantized keys: `PosKey`/`ExtentKey` store
`QuantizeToCells` cell indices (lines 37-38, 100-102), so two scan boxes whose half-extents
differ by up to 50 m per axis pass the "exact match" check and share cached results.

Failure: BaR A scans with ~20 m half-extents; nearby BaR B scans with ~45 m half-extents,
centers in the same 50 m cell → both quantize to identical posKey/extentKey, entry
verification passes, and B is served A's entity list for the 4 s TTL. Grids/floating objects
in the 20-45 m shell are invisible to B's scan and never become targets. The doc comment
(lines 28-30) claims different-size boxes are treated as a miss; that only holds across cell
boundaries.

## Root Cause
Verification compares the quantized values instead of the raw center/extents.

## Fix
Store the raw `Vector3D` center and half-extents in the entry and compare those (with a small
epsilon) during verification; keep the quantized key only for bucketing.
