# BUG-261023.2: Projected blocks are created with their first component for free — item duplication (PR #148)

## Status: Open
## Severity: High
## Version: v2.5.6
## Found In: REVIEW-261023.1 #2 / GitHub PR #148 by BlazedLucario (closed by the author, unmerged) — `NanobotSystem.Welding.cs:579-750` (`ServerDoWeld` projected path, `proj.Build` at :622)

## Description
`proj.Build(target, owner, builder: _Welder.EntityId, ...)` materialises the block via
`MyCubeGrid.BuildBlock`, which calls `BuildComponent.AfterSuccessfulBuild(builder)` →
`MySpaceBuildComponent.TakeMaterialsFromBuilder(builder)`. Verified against the game assemblies (IL call
graph): that method takes the creation component (Components[0] x1) from the **builder entity's own
inventory** — `GetItemAmount` then `RemoveItemsOfType` — and silently takes nothing if it isn't there.

BaR stages the creation component in the detached `_TransportInventory` (creation-first pick in
`ServerFindMissingComponents`, :899-940), never in the welder inventory, so the engine finds nothing and
the block appears with Components[0] already mounted. The transported creation item is then stockpiled as
one of the remaining components. Net: every projected block BaR builds costs one component less than it
returns when ground — a repeatable dupe (project → build → grind → +1 component per block).

## Steps to Reproduce
1. Survival. Projector with a 1-block blueprint (e.g. heavy armor), BaR with AllowBuild, exact stock in cargo.
2. Let BaR build and fully weld it; count components consumed from cargo.
3. Grind the block with a hand grinder; compare components returned.
4. Returned = consumed + 1 (Components[0]).

## Root Cause
The code assumed `proj.Build()` consumes components internally ("manual RemoveItems is not needed");
the engine only consumes from the builder's real inventory, which BaR never fills with the creation item.

## Fix
Proposed (not implemented):
Adopt PR #148's approach on `fix/v2.5.6` (credit BlazedLucario):
- Before `proj.Build`, snapshot `welderInventory.GetItemAmount(Components[0].Definition.Id)`.
- After a successful build **and** physical-block resolve (`created = true`), if not creative and the
  welder amount did not drop, remove 1 of that component from `_TransportInventory`
  (`RemoveItemsOfType(1, id)`). The projected path already guarantees the transport holds ≥1 of it (:588).
- No charge on budget deferral (`projBuildSlot`), NRE, or silent build failure (no block created).
- Fix the misleading comment at the build site. Add a profiler field (`creationCharged=`).
