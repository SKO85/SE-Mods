# BUG-260612.26: _PushTargetsFull armed from a ≤4-item sample — sorter-blocked head items stall pushing in drips

## Status: Open
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260612.1 #L10 — `NanobotSystem.Inventory.cs:80-136`

## Description
The chunked push attempts at most 4 items (or 5 ms) per call; `anyAttempted && !anyPushed` then marks the entire target set full for 15 s. If those particular head items are sorter-blocked while other welder items would push fine, pushing proceeds in 4-item/15-second drips. Self-healing (the cursor advances across retries) — mainly a diagnosis trap for "BaR pushes slowly" reports.

## Root Cause
Full-set verdict derived from a small per-call sample.

## Fix
Only arm `_PushTargetsFull` after a full cursor wrap with zero pushes (track wrap position), or skip-and-continue past unpushable items within the per-call budget before concluding.
