# BUG-261122.13: Companion script displays start on the second configured page

## Status: Open
## Severity: Low
## Version: v2.5.6 (companion script)
## Found In: CompanionScriptBehaviourTests (2026-11-22) — Script.cs `RefreshDisplay`

## Description
`DisplayEntry` starts with `DisplayKindIdx = 0` and `NextSwitchTime = 0`, and the first refresh advances the index
before drawing, so a display configured `Kinds=Status,WeldTargets,...` first shows WeldTargets; the first page
appears only after a full rotation (and a single-kind display is unaffected).

## Fix (proposed)
Draw first, advance after: start `DisplayKindIdx = -1`, or set `NextSwitchTime = elapsed + SwitchTime` on init.
Add a unit test asserting the first page on the first run.

## Scenario
SCN-API-002 (CompanionScriptBehaviourTests).
