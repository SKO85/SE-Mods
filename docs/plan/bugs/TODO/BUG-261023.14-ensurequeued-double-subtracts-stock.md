# BUG-261023.14: Companion auto-queuing under-queues: assembler output stock is subtracted twice

## Status: Open
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-261023.1 #14 — `Utils/UtilsProductionBlock.cs:57-121` (`EnsureQueued`), `NanobotSystem.Welding.cs:1470-1487` (aggregate source subtraction)

## Description
Since BUG-260824.2 the aggregate `MissingComponents` is already net of stock in connected sources —
which include assemblers' output inventories (FEAT-011). `EnsureQueued` then subtracts the assembler's
output inventory again (plus its queue). Example: need 100, 30 sitting in the assembler output →
aggregate reports 70 → EnsureQueued queues 70 − 30 = 40 → total available 70, short by 30 until BaR pulls
the output. It converges, but slower than intended.

## Steps to Reproduce
Empty cargo, assembler with 30 SteelPlate in its output, BaR needing 100 → watch the queued amount.

## Root Cause
Two layers each subtract the same stock.

## Fix
Proposed (not implemented):
Either subtract only the queue (not the output inventory) when called with an aggregate that is
already net of sources, or exclude production-block output inventories from the aggregate's source
subtraction. `EnsureQueued` is public scripting API — prefer changing the aggregate side.
