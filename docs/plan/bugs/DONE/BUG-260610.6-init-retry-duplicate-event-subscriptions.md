# BUG-260610.6: Init() early-return retry path duplicates event subscriptions and leaks a half-initialized registration

## Status: Fixed
## Severity: High
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `NanobotSystem.Init.cs:118-192`, `Mod.cs:368-371`

## Description
`Init()` registers the block in `Mod.NanobotSystems` (:128) and subscribes events (:143-158) *before* the `welderInventory == null` early return (:161-162) that leaves `_IsInit = false`. `UpdateBeforeSimulation10_100` retries `Init()` every 10th frame (`Update.cs:133`); each retry:

- appends another lambda to `_onEnabledChanged` / `_onIsWorkingChanged` via `+=`, and re-subscribes the accumulated multicast to `_Welder.EnabledChanged` / `IsWorkingChanged` — after N retries one Enabled toggle runs O(N²) handler invocations;
- leaves the half-initialized instance (`_TransportInventory == null`) visible to `Mod.SettingsChanged()`, whose second loop (Mod.cs:370 — no null guard, no try/catch) dereferences `_TransportInventory.MaxVolume` (Init.cs:74) → NRE aborts the settings fan-out for all remaining BaRs;
- `Close()` is fully gated on `if (_IsInit)` (:201), so such a block is never removed from `Mod.NanobotSystems` and never unsubscribes `AppendingCustomInfo` (subscribed unconditionally in the public `Init(MyObjectBuilder...)`, :37) — a permanent stale entry touched by `SettingsChanged`/`GetEffectiveStaggerGroupCount`/`FriendlyRelationsHandler.Rebuild`.

## Root Cause
Registration and event subscription precede the early-exit validation; lambdas are accumulated with `+=` on every attempt.

## Fix
Commit 5379e7a on `fix/v2.5.6`. Three changes in `NanobotSystem.Init.cs`:

1. The `welderInventory == null` check (the only early return after registration) moved to the top of the private `Init()`, before `Mod.NanobotSystems.TryAdd` and the event subscriptions — a failed attempt now leaves no trace, and `Mod.SettingsChanged`'s fan-out can never see an instance without `_TransportInventory`.
2. Handler lambdas are created once (`if (null) { _onEnabledChanged = ... }`) and subscribed with an unsubscribe-then-subscribe pair, making the subscription idempotent under any retry pattern (including a hypothetical exception between subscribe and `_IsInit = true`).
3. `Close()` restructured: the `AppendingCustomInfo`/`EnabledChanged`/`IsWorkingChanged` unsubscribes and the `Mod.NanobotSystems.TryRemove` now run unconditionally (outside the `if (_IsInit)` block), since `AppendingCustomInfo` is subscribed in the public `Init(MyObjectBuilder...)` regardless of init success.
