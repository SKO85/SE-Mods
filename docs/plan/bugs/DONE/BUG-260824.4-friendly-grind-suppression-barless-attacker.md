# BUG-260824.4: Friendly grind-damage suppression only works when the attacker owns a BaR

## Status: Fixed
## Severity: High
## Version: v2.5.6
## Found In: REVIEW-260824.1 — `Handlers/DamageHandler.cs:114`, `Handlers/FriendlyRelationsHandler.cs:133-139`

## Description
`FriendlyRelationsHandler.Rebuild()` keys `_OwnersByOwner` exclusively by welder OwnerIds,
so `TryGetOwnersForOwner(attackerId)` misses for any attacker who owns no BaR and
`MarkFriendlyDamage` never fires.

Failure: faction member B (no BaR) hand-grinds a block on the faction base while member A's
BaR repairs it. Old code called `welder.GetUserRelationToOwner(B)` per welder and paused the
repair; new code misses the cache lookup, so the BaR instantly re-welds everything B grinds —
deliberate disassembly becomes impossible. Also fails for ALL attackers during the first
~15 s after world load (cache empty until the first periodic Rebuild).

## Root Cause
Friendly-relations cache built only over BaR owners instead of resolving the attacker's
relation to each welder owner.

## Fix
New `FriendlyRelationsHandler.TryGetOrComputeOwnersForOwner`: on cache miss (attacker
owns no BaR, or cache not yet built) computes friendly welder-owners against live
welders and memoizes until the next Rebuild swap; cleared in Clear(). DamageHandler
uses the new variant. Commit 81561a9, BuildId 260824.2.
Files: `FriendlyRelationsHandler.cs`, `DamageHandler.cs`.
