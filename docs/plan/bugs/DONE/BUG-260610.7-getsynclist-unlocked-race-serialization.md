# BUG-260610.7: GetSyncList() enumerates target lists without the lock — races background scan swap during state serialization

## Status: Fixed
## Severity: High
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `Collections/TargetBlockDataHashList.cs:12-23`, `Collections/TargetEntityDataHashList.cs:12-23`, `Models/SyncBlockState.cs:344-436`

## Description
`RebuildHash()` takes `lock(this)`, but `GetSyncList()` does not. It is invoked lazily on the main thread during ProtoBuf serialization (the `PossibleWeldTargetsSync` / `PossibleGrindTargetsSync` / `PossibleFloatingTargetsSync` / `MissingComponentsSync` getters, triggered by `MyAPIGateway.Utilities.SerializeToBinary` in `MsgBlockStateSend`, `NetworkMessagingHandler.cs:482-484`). Meanwhile the background scan thread swaps the same lists under `lock(State.PossibleWeldTargets) { Clear(); AddRange(); RebuildHash(); }` (`Scanning.cs:1182-1224`). A `foreach` over a `List<T>` being concurrently cleared/refilled throws `InvalidOperationException` (version check) or reads torn data. Every other reader in the codebase (CustomInfo, Welding, Grinding, Scripting) takes the lock — the serialization path is the one omission. The exception is swallowed without logging by `MsgBlockStateSend`'s catch (see BUG-260610.41), so the symptom is silently dropped state packets → client desync with no log trace. Found independently by two reviewers.

## Root Cause
Lock convention broken on one of the four access paths to the shared HashLists.

## Fix
Commit 05f1917 on `fix/v2.5.6`. Wrapped the enumeration in `lock (this)` (the same lock object the scan swap and `RebuildHash` use) in all three sync collections: `TargetBlockDataHashList`, `TargetEntityDataHashList`, and `DefinitionIdHashDictionary` (backs `MissingComponentsSync` — same race, same convention; the scan swaps `State.MissingComponents` under its lock too). Runs at most once per 1-2 s sync interval, so the added lock hold is negligible. The silent catch that masked this remains tracked as BUG-260610.41. BuildId → 260610.5. Build: Debug, 0 errors.
