# BUG-260612.23: COLLECT_FLOATINGOBJECTS_SIMULTANEOUSLY cap (50) is unreachable — dead guard

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260612.1 #L7 — `NanobotSystem.cs:52, 58`, `NanobotSystem.Collecting.cs:58`, `NanobotSystem.Scanning.cs:1013`

## Description
The collect loop breaks at `collectingCount >= 50`, but the floating-target list is capped at `MaxPossibleFloatingTargets = 16` at scan-apply time, so the count can never reach 50. The only effective caps are the 16-entry list and the transport-volume gate; the comment describes a limit that never triggers.

## Root Cause
Constants diverged over time.

## Fix
Either lower the constant below 16 (if a per-sweep cap is desired) or remove the dead guard and comment.

**Resolution:** commit 5f9466c (BuildId 260612.9) on `fix/v2.5.6` - unreachable 50-target cap and the COLLECT_FLOATINGOBJECTS_SIMULTANEOUSLY constant removed (floating list is capped at 16 at scan-apply; the transport-volume gate is the real cap). Build: Debug, 0 errors.
