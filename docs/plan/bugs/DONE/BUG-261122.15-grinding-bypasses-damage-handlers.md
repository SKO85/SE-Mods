# BUG-261122.15: BaR grinding bypasses BeforeDamage handlers (protection plugins / mods cannot stop it)

## Status: Fixed
## Severity: High (server admins rely on protection plugins)
## Version: v2.5.6 (all versions since the original mod)
## Found In: protected-grid review 2026-11-22 — `NanobotSystem.Grinding.cs` `ServerDoGrind`

## Description
`ServerDoGrind` builds a Grind `MyDamageInformation` but calls `DecreaseMountLevel` directly; the BeforeDamage event
was never raised (the original mod had it commented out as "Not available in modding"). Vanilla grinders raise it, and
protection plugins / mods that veto grinding through a damage handler (Amount = 0) were bypassed by the BaR. Grids made
indestructible (`DestructibleBlocks = false`) or immune were already skipped at scan time.

## Fix
- `RaiseGrindDamage`: `IMyDamageSystem.RaiseBeforeDamageApplied(target, ref info)` before the dismount gate; the
  (possibly reduced) amount is used; Amount <= 0 -> no grind, grind slot refunded, profile reason `grindRefused`.
- Performance: a refused grid is skipped by that BaR for 30 s (`_grindRefusedGrids`, checked only while non-empty;
  expired entries dropped on lookup) — one event per grid per 30 s instead of one per tick. `skipRefused` in the
  ServerTryGrinding profile.
- DefenseShields does not veto BaR grinding through the damage event: S60 (ShieldCheckEnabled=false) still grinds
  through a raised shield, so the setting keeps deciding.

## Scenario
SCN-GRIND-006 — unit:GrindDamageVetoTests; ingame:S73 (indestructible), S74 (damage-handler protection).

## Resolution
Verified in game, BuildId 261122.25 (2026-11-22): the mod loads (RaiseBeforeDamageApplied is allowed for mods); S74 —
plugin-style handler refused the grind, 1 grind attempt in 20 s, nothing ground; S73 — indestructible grid, 0 attempts;
S60 / S61 unchanged with DefenseShields. Unit: GrindDamageVetoTests (3).
