# BUG-261023.9: Settings changes trigger redundant forced rescans (per BaR twice; every BaR on any mod setting)

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-261023.1 #9 — `NanobotSystem.Update.cs:297-315`, `NanobotSystem.Init.cs:104`, `Mod.cs:390-393`

## Description
- A client's terminal change is applied in `MsgBlockSettingsReceived` (`SettingsChanged()` → forced
  rescan), and the Changed bit then makes `UpdateBeforeSimulation10_100` call `SettingsChanged()` again
  within ~1 s → second forced rescan.
- Script-controlled setups that set `CurrentPickedTarget` every PB run flip `Settings.Changed` → a forced
  rescan (debounce bypassed) every ~1.7 s per BaR.
- Any `/nanobars config set` runs `SettingsChanged()` on every BaR, each forcing a rescan with
  `bypassDebounce: true` — all clusters scan in the same frame.

## Steps to Reproduce
Profile `ImmediateRescanTrigger` while (a) toggling a terminal setting from a DS client, (b) running a script that sets CurrentPickedTarget, (c) `config set DebugMode true` with 50 BaRs.

## Root Cause
SettingsChanged doubles as "rescan now" for every kind of change.

## Fix
Implemented (BuildId 261023.6) for the part that is real; two parts dismissed after cross-checking.
- **Fixed — script picked targets**: `SettingsChanged(bool forceRescan = false)` now forces the
  (debounce-bypassing) rescan only when `ComputeSettingsScanKey` changed — the cluster key hash (work/
  search mode, cluster-relevant flags, colours, janitor, weld options, priority lists, owner, zones)
  plus `AreaSize`, `AreaOffset` and all `Flags`. A script moving `CurrentPicked*Block` (or a sound
  volume change) no longer forces a full rescan on every pick; CheckLimits, power, custom info and the
  cluster re-key release still run.
- `Mod.SettingsChanged` passes `forceRescan: true` — mod-level changes can alter the scan without
  changing per-BaR settings.
- **Dismissed — "DS client change → two forced rescans"**: `AssignReceived` sets `Changed = 2u` (save
  only, no transmit bit), so the update loop does not call `SettingsChanged()` a second time.
- **Dismissed — "`config set` makes all clusters scan in the same frame"**: each coordinator rescans
  from its own update slot (spread over frames) and the scans run on the background pool; one round of
  rescans per admin config change is acceptable.

Files: `NanobotSystem.Init.cs`, `NanobotSystem.cs`, `Mod.cs`.
Verification: unit — `SettingsScanKeyTests` (picked target / sound volume leave the key unchanged;
area size, area offset, work mode, flags change it). In-game: pending — SCN-TERM-001 (profile
`ImmediateRescanTrigger` while a script picks targets).
