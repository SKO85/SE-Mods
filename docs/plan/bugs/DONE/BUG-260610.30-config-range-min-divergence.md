# BUG-260610.30: `config set Range 1` creates permanent server/client settings divergence

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `Chat/Commands/ConfigCommand.cs:39-41`, `Models/SyncModSettings.cs:319`

## Description
The `config set` path mutates `Mod.Settings` directly and never runs `ValidateAndClamp`, but `ClientMsgModSettingsReceived` does run it on the broadcast (:192). ConfigCommand allows `Range` min=1 while `WELDER_RANGE_MIN_IN_M` = 2: setting Range to 1 leaves the server at 1 while every client clamps to 2 — `CheckLimits`-derived `MaximumRange`/transport-speed values then differ between server and clients.

## Root Cause
Command-side min diverges from the model's clamp constant; no re-validation after `config set`.

## Fix
Align the command's min with `WELDER_RANGE_MIN_IN_M` (or run `ValidateAndClamp` after every `config set`).

**Resolution:** commit 9270feb (BuildId 260610.19) on `fix/v2.5.6` - Range bounds in ConfigCommand now use NanobotSystem.WELDER_RANGE_MIN_IN_M / WELDER_RANGE_MAX_IN_M so the command can never accept a value the client-side clamp rejects. Build: Debug, 0 errors.
