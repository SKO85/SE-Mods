# BUG-261023.13: RazeQueueHandler.Process swallows exceptions without logging

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-261023.1 #13 — `Handlers/RazeQueueHandler.cs:208-215`

## Description
The outer `catch` only writes a profiler line (`exception=true`) when profiling is on; otherwise the
exception disappears. A drain that throws every time (bad queued block state) would silently stop razing
fully-dismounted blocks. Same class as BUG-260909.2.

## Steps to Reproduce
n/a (code inspection).

## Root Cause
Profiler-only error reporting.

## Fix
Implemented (BuildId 261023.6), `Handlers/RazeQueueHandler.cs`: the catch now logs at Error with the
exception — the first failure, then at most once per 60 s with the number of failures since the last
report (a drain that throws every tick would otherwise flood the log). Profiler line kept; state reset
in `Clear()`.

## Scenario
no scenario: logging-only

## Related
BUG-260909.2, BUG-260522.2
