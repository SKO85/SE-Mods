# BUG-261023.11: TtlCache.CleanupExpired can delete a claim refreshed between its two passes

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-261023.1 #11 — `Caches/TtlCache.cs` (`CleanupExpired`), `Managers/PeriodicMaintenanceScheduler.cs` (`_assignmentCleanup` runs on the background pool), `Handlers/BlockSystemAssigningHandler.cs:108`

## Description
`CleanupExpired` collects expired keys, then `TryRemove`s them. `BlockSystemAssigningHandler.Cleanup`
runs every 5 s on a background thread while the main thread re-claims (`Set`) lock-on blocks every tick.
A claim that lapsed and is re-claimed between the two passes is removed — another BaR can then take the
block. The handler's comment ("all assignment ops are main-thread") is wrong for cleanup. Short window
in-game (one cleanup every 5 s), mild effect (claim churn / brief double targeting) — but the unit test shows the
race drops most refreshes when they overlap a cleanup.

## Steps to Reproduce
Hard to reproduce deterministically; race between background cleanup and main-thread Set.

## Root Cause
Unconditional `TryRemove(key)` after a non-atomic expiry check.

## Fix
Implemented (BuildId 261023.6), `Caches/TtlCache.cs`: `CleanupExpired` collects the expired
key/value pairs and removes each with `ICollection<KeyValuePair<,>>.Remove(pair)` — ConcurrentDictionary's
atomic remove-if-value-matches — so an entry refreshed by `Set()` between the two passes survives.
`CacheItem` equality is the default struct compare (bitwise for the value types used; only runs on
expired entries). `IEquatable<T>` deliberately not added (in-game whitelist can't be verified at build
time). Handler comment corrected (cleanup runs on the background pool).

Verification: unit — `TtlCacheTests.CleanupExpired_KeepsEntriesRefreshedWhileItRuns` (20000 expired
claims re-claimed on the test thread while cleanup loops on another): 0 lost with the fix, ~18000 lost
with the old code (3/3 runs) — the race is real, though the in-game window is far shorter.

## Scenario
SCN-BUDGET-001 (concurrent cleanup test)
