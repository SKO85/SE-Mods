# BUG-260610.40: Per-instance sort caches retain IMySlimBlock keys between scans

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `NanobotSystem.cs:213-214`, `NanobotSystem.Scanning.cs:644`

## Description
`_sortCandidateDistances`, `_sortCandidatePriorities`, and `_ScanPreSortDistances` are cleared only at the start of the next use (and the partition-pass clear at `Scanning.Block.cs:1117-1118` only runs on the member-aware path). If a cluster shrinks to solo or a BaR goes idle, the last scan's block references — potentially on since-deleted grids — stay rooted in the dictionaries until the BaR is closed or the next multi-member scan. Bounded size (one scan's candidates), so it's reference pinning rather than growth, but it keeps closed grids alive.

## Root Cause
Clear-on-next-use instead of clear-after-use.

## Fix
Clear the dictionaries in `AsyncClusterScan`'s `finally` (alongside `_ClusterMemberAreaCenters/Boxes`, `Scanning.cs:605-608`).

**Resolution:** commit 35c2785 (BuildId 260610.29) on `fix/v2.5.6` - AsyncClusterScan finally clears _ScanPreSortDistances, _sortCandidateDistances and _sortCandidatePriorities alongside the existing member-snapshot clears. Build: Debug, 0 errors.
