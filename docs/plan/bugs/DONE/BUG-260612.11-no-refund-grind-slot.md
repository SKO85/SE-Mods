# BUG-260612.11: Grind count slot never refunded when dismount/mech gates reject — asymmetric with the weld-slot refund

## Status: Fixed
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-260612.1 #M4 — `NanobotSystem.Grinding.cs:170, 368-382, 424-445`, cf. `Mod.cs` RefundWeldSlot

## Description
BUG-260610.35 added `Mod.RefundWeldSlot()` for the weld path when a downstream gate rejects after the weld slot was claimed. The grind path has the identical pattern — `TryClaimGrindSlot` debited, then the dismount gate (`TryClaimDismountSlot`, 3/tick) rejects before any work — and never refunds; there is no `RefundGrindSlot` at all. With many BaRs finishing blocks simultaneously, most of the shared grind count budget is consumed by no-op bounces, starving BaRs that could actually grind.

## Root Cause
The .35 fix pattern was only applied to welding.

## Fix
Add `Mod.RefundGrindSlot()` (PerTickBudget.Refund already exists) and call it on the dismount-gate rejection path (and evaluate the mech-gate path — see BUG-260612.20 for its separate mis-reporting issue).

**Resolution:** commit 07b4588 (BuildId 260612.2) on `fix/v2.5.6` - new Mod.RefundGrindSlot() (PerTickBudget.Refund); called on the dismount-gate rejection in ServerDoGrind before any grind work - mirrors the BUG-260610.35 weld-slot refund. The mech-gate path is intentionally NOT refunded (real work already ran there; tracked as BUG-260612.20). Build: Debug, 0 errors.
