# BUG-260610.12: NanobotSystem.Close() does not release the system's block assignments

## Status: Fixed
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `NanobotSystem.Init.cs:199-273`

## Description
`Close()` nulls `CurrentWeldingBlock`/`CurrentGrindingBlock` (correctly decrementing grid counts, BUG-160) but never calls `BlockSystemAssigningHandler.ReleaseAllForSystem(_Welder.EntityId)` — which exists and is already used in `Mod.ReleaseSurplusLockOnsForLoweredLimit` and `SettingsChanged`. All TTL claims held by the closing BaR stay live for up to `AssignmentTtlSeconds` (≤30 s), blocking other BaRs from those blocks after the system is grinded/deleted.

## Root Cause
Missing release call in the close path.

## Fix
Commit 634e5a1 on `fix/v2.5.6`. `Close()` now calls `BlockSystemAssigningHandler.ReleaseAllForSystem(_Welder.EntityId)` right after the `CurrentWeldingBlock`/`CurrentGrindingBlock` nulls, gated on `Mod.Settings.AssignToSystemEnabled` (same pattern as `SettingsChanged`). BuildId → 260610.10. Build: Debug, 0 errors.
