# BUG-260609.1: Push-full 15s backoff quantized to source-scan cadence (~30s)

## Status: Fixed
## Severity: Medium
## Version: v2.5.5
## Found In: Codex PR review — `NanobotSystem.Scanning.cs` / `NanobotSystem.Inventory.cs`

## Description
The 15s `_PushTargetsFull` safety backoff (introduced by BUG-260526.2, shortened
from 60s) did not actually permit a 15s retry. The reset check lived inside
`if (result.SourcesUpdated)` in `ApplyClusterResultToSelf`, and `SourcesUpdated`
is only produced on a source rescan (`SourcesUpdateInterval`, default 30s).

As a result, `_PushTargetsFull` could not clear sooner than the next source
refresh, so recovery stayed quantized to ~30s (or longer). When a player freed
space in an *existing* container, the push targets' signature was unchanged (no
add/remove), so the `pushTargetsChanged` path didn't fire either — the BaR stayed
idle until the next source scan instead of retrying after 15s.

## Steps to Reproduce
1. Run a BaR with a Push* flag enabled until its push targets fill up
   (`_PushTargetsFull` becomes true).
2. Free space in one of the existing push containers (do not add/remove a
   container, so the push-target signature stays the same).
3. Observe the BaR does not resume pushing for up to ~30s (next source scan),
   despite the intended 15s window.

## Root Cause
The time-based backoff (`ElapsedPlayTime - _PushTargetsFullSince >= 15`) ran only
inside the `result.SourcesUpdated` branch of `ApplyClusterResultToSelf`
(`NanobotSystem.Scanning.cs`). That branch executes on the background scan apply
and only when a source rescan occurred, so a wall-clock backoff there is
effectively clamped to `SourcesUpdateInterval` (30s).

## Fix
- `NanobotSystem.Inventory.cs:50` — moved the 15s time-based retry to the
  main-thread consumer `ServerTryPushInventory`, at the `_PushTargetsFull`
  early-return. This runs every tick (`NanobotSystem.Operations.cs:82`), so the
  flag now clears 15s after it was set regardless of scan cadence;
  `PushComponents` re-marks it if containers are still full. The shared field
  also unblocks `ServerEmptyTransportInventory` (runs later in the same tick).
- `NanobotSystem.Scanning.cs:1251` — scan-apply block now keeps only the
  signature-change reset (container added/removed), which genuinely needs the
  freshly-scanned push-target list. The dead/quantized time-based path was
  removed with an explanatory comment.
- `Constants.cs` — BuildId bumped to `260609.1`.

Related: BUG-260526.2 (original 60s→15s shortening), BUG-016 (push-target full
flag).
