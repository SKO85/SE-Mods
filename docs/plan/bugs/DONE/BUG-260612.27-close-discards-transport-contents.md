# BUG-260612.27: Close() discards _TransportInventory contents — in-flight load deleted on block destruction

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260612.1 #L11 — `NanobotSystem.Init.cs:216-305`

## Description
The teardown clears lists and state but never drains the phantom transport inventory back to the welder block (whose own contents the engine drops on destruction). A BaR destroyed or closed mid-grind/collect deletes its in-flight load (up to `_MaxTransportVolume`); the transport inventory is also not serialized, so unloading a world mid-transport loses the same items.

## Root Cause
Transport inventory is mod-side phantom storage with no teardown drain.

## Fix
In `Close()` (before state teardown), attempt `ServerEmptyTransportInventory`-style drain to the welder inventory; leftovers could be spawned as floating items if the welder is full. Consider the same on `SaveData` for the unload case (or accept and document the unload loss).

**Resolution:** commit ea784a0 (BuildId 260612.10) on `fix/v2.5.6` - Close() best-effort drains the transport inventory back to the welder block via ServerEmptyTransportInventory(false) (welder contents drop as loot on destruction) before teardown. Build: Debug, 0 errors.
