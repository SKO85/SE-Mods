# BUG-260612.25: Overflow push ignores per-type push flags — can push out components needed for welding

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260612.1 #L9 — `NanobotSystem.Inventory.cs:174-182`, `Utils/UtilsInventory.cs:48`

## Description
The safety/overflow push in `ServerEmptyTransportInventory` is gated on "any of the three Push* flags set" but then calls the push-everything overload `PushComponents(_PossiblePushTargets, null)`, which moves every item type. With only `PushIngotOreImmediately` enabled, components the welder needs are pushed out to cargo. Inconsistent with `ServerTryPushInventory`'s careful per-type eligibility.

## Root Cause
Overflow path reuses the unfiltered push helper.

## Fix
Make the overflow push honor the same per-type eligibility as `ServerTryPushInventory` (push only item types whose flag is enabled).

**Resolution:** commit ea784a0 (BuildId 260612.10) on `fix/v2.5.6` - the overflow push walks the welder inventory and pushes only item types whose Push* flag is enabled (same eligibility as ServerTryPushInventory) instead of the push-everything call; full-pass verdict keeps the targets-full marking sound.
