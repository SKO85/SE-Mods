# BUG-260612.24: EmptyFloatingObject removes the floating object before AddItems and ignores the result — hardening

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260612.1 #L8 — `NanobotSystem.Collecting.cs:170-181`

## Description
The full-pickup branch calls `MyFloatingObjects.RemoveFloatingObject(floating)` before `dstInventory.AddItems(...)` and doesn't check the add result. Currently unreachable as a loss path — `remainingVolume` is computed against the logical `_MaxTransportVolume` while the real transport inventory is much larger — so this is hardening against future volume-math changes, not an active bug. Pre-existing original-mod code.

## Root Cause
Remove-then-add ordering with unchecked add.

## Fix
Add first, then remove on success (or check the AddItems result and skip the removal on failure).

**Resolution:** commit 5f9466c (BuildId 260612.9) on `fix/v2.5.6` - EmptyFloatingObject verifies CanItemsBeAdded BEFORE RemoveFloatingObject — hardening; the loss path was unreachable with current volume math. Build: Debug, 0 errors.
