# BUG-260610.11: Static handler state holding game objects never cleared in UnloadData — cross-world leaks and stale-state corruption

## Status: Fixed
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `Mod.cs:441-503` (UnloadData), multiple handlers

## Description
`Mod.UnloadData` clears `BlockSystemAssigningHandler`, `BlockFailureCooldownHandler`, `ScanClusterCoordinator`, `SharedGridBlockCache`, `SharedEntityCache` — but misses:

- `FriendlyRelationsHandler._BaRsByOwner` (holds `NanobotSystem` references → entire welder/grid object graphs) and `_DamageByOwner` (`IMySlimBlock` refs) — `FriendlyRelationsHandler.cs:26-36`.
- `RazeQueueHandler._queue` / `_pendingKeys` (`RazeQueueHandler.cs:31, 38`) — the first `Process()` in the next world calls `RazeBlocks` against grids of the dead world, or with EntityId reuse razes positions on the wrong grid.
- `GridOwnershipCacheHandler.Cache` + `GridLastAccess` (`GridOwnershipCacheHandler.cs:19, 27`) — TTL expirations are absolute session-clock values (`TtlCache.cs:84`) and the clock resets per world, so old entries appear unexpired in the new world; an EntityId collision returns a wrong ownership relation (grind/weld authorization data).
- `Mod.GridSystemCount` (`Mod.cs:41`) — stale counts make `GridSaturationTracker.Rebuild()` mark fresh grids saturated, idling BaRs.
- `BlockPriorityHandling.GetItemKeyCache` (`BlockPriorityHandling.cs:42`) — same stale-clock issue; collision returns a wrong block class/priority.
- `GridScanCache` (`Cluster/GridScanCache.cs`) — never cleared on unload; additionally `Invalidate()` has no callers and `MaybeCleanup` only runs from `Set()` when `Count >= 32`, so once scanning stops, expired entries holding closed-grid `IMySlimBlock` refs are pinned for the process lifetime.
- `SafeZoneHandler.Zones` is also only cleared via `Unregister` when the session is still available (see BUG-260610.27).

## Root Cause
Unload-clear list has not kept up with new static handlers/caches.

## Fix
Commit 63c4cb2 on `fix/v2.5.6`. Added `Clear()` methods where missing and wired all of them into `Mod.UnloadData` (each in its own `try/catch`, alongside the existing clears):

- `FriendlyRelationsHandler.Clear()` — swaps `_BaRsByOwner`/`_OwnersByOwner` to fresh empty dicts (volatile swap, consistent with `Rebuild()`), clears `_DamageByOwner` + reap buffer under `_DamageLock`.
- `RazeQueueHandler.Clear()` — purges `_queue`, `_pendingKeys`, `_batchByGrid`, resets `_tickCounter`.
- `GridOwnershipCacheHandler.Clear()` — clears `Cache` (session-clock TTL entries) and `GridLastAccess`.
- `Mod.GridSystemCount.Clear()`, `BlockPriorityHandling.GetItemKeyCache.Clear()`, `GridScanCache.Clear()` — direct calls (methods already existed).

`SafeZoneHandler.Zones` clearing is covered by the BUG-260610.27 fix (commit 901f0b8). The `GridScanCache.Invalidate(gridId)`-on-grid-close idea was noted as optional in the ticket and skipped (TTL + unload clear suffice; no grid-close hook exists today). BuildId → 260610.9.
