# BUG-261123.9: Range below 100 m makes the transport speed 0 — an error on every delivery

## Status: Done
## Severity: Medium
## Version: v2.5.7 (bug since the v2.0 rewrite, 2025)
## Found In: full local test run 261123.62 — S25 logged 42 errors (new errors-logged metric)

## Description
`SyncBlockSettings.CheckLimits`: `rangeScale = Math.Min(Mod.Settings.Range / WELDER_RANGE_DEFAULT_IN_M, 4f)` divides
two ints. With the mod setting Range 2..99 m the scale is 0, the weld / grind / collect transport speeds are 0, and
`TimeSpan.FromSeconds(2 * distance / 0)` throws "TimeSpan overflowed" on every delivery (UpdateBeforeSimulation10
exception in the log, possibly the mod's error notification on the HUD). Welding still happened by accident (the
failed delivery left a zero transport time). Ranges 100-399 were also truncated (150 behaved like 100). A welding /
grinding multiplier of 0 had the same effect.

## Fix
`NanobotSystem.TransportRangeScale(range)` = range / 100 as float, max 4; `NanobotSystem.TransportTime(distance,
speed)` used by weld, grind and collect: zero / tiny speed -> 60 s cap, NaN / negative distance -> 0, never throws.
Unit: TransportTimeTests. Harness: every scenario now fails when the mod logs an error during the run
(`TestScenarioBase.AllowsModErrors` to opt out), so this class of bug cannot pass silently again.

## Scenario
SCN-CFG-001 — ingame:S25 (Range 20 m, now must log no errors); unit:TransportTimeTests.

## Resolution
Fixed in BuildId 261123.63. In game: S25 passes with 0 errors logged (was 42).
