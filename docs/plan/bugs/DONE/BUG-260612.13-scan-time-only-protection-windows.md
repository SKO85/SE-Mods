# BUG-260612.13: Zone/shield protection is scan-time only — activation windows of up to ~20 s

## Status: Fixed
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-260612.1 #M6 — `NanobotSystem.Operations.cs:152-156`, `Handlers/SafeZoneHandler.cs:265-271`, `NanobotSystem.Scanning.Block.cs:344-372`

## Description
Neither the weld nor the grind execution loop re-checks zones or shields (verified by grep); every protection decision is baked into the scan-time target lists, so each cache TTL is a real action window:

- Zone enabled/created/moved onto a grid: the `zoneId == 0` ("no zone") cache hit never revalidates → ~15 s cache + ~5 s scan swap of continued grinding. ("Zone disabled" IS detected promptly — only the negative entry is blind.)
- BaR-side flag flips (`SafeZoneAllows*`): ~2 s refresh + ~5 s scan; flips never purge target lists or break lock-on.
- Target's shield raised: ~2 s scan interval + 3 s `GridScanCache` (params hash covers only the welder's own shield, not the target's).

## Root Cause
Single-layer (scan-time) enforcement with TTL caches.

## Fix
Cheapest meaningful close: gate `MultiWeld`/`MultiGrind` on the live `State.SafeZoneAllows*` flags (two flag checks per tick), re-check `IsShieldProtected(CurrentGrindingBlock)` before `ServerDoGrind`, and make the `zoneId == 0` cache entry shorter-lived or validating against the zone set version.

**Resolution:** commit 090ab37 (BuildId 260612.4) on `fix/v2.5.6` - execution-time gates: MultiWeld returns early when !State.SafeZoneAllowsWelding, MultiGrind when !State.SafeZoneAllowsGrinding (mirrors the scan-time gates, ~2 s flag refresh); the grind loop re-checks IsShieldProtected + SafeZoneHandler.IsProtectedFromGrinding on the chosen target before claiming the budget (releases assignment and skips on hit); no-zone cache entries now expire after 5 s (positives keep 15 s) so zone activation is honored in ~5 s.
