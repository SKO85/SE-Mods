# BUG-260610.20: Culture-sensitive float.TryParse in config/sim chat commands mis-parses on non-US locales

## Status: Fixed
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `Chat/Commands/ConfigCommand.cs:419`, `Chat/Commands/SimCommand.cs:28`

## Description
`float.TryParse(s, out v)` uses the server OS culture. On comma-decimal locales (de-DE etc.) `"2.5"` parses as **25** (the `.` is treated as a group separator), so `/nanobars config set WeldingMultiplier 2.5` silently sets 25 — inside the 0.1–100 range, so no error is reported. `/nanobars sim 0.5` parses as 5 and is rejected with a confusing range error.

## Root Cause
Default-culture parse for user-typed numeric arguments.

## Fix
Commit b6afdf6 on `fix/v2.5.6`. `ConfigCommand.FloatSetting`: parse via `NumberStyles.Float` + `CultureInfo.InvariantCulture`, and `Get` formats with invariant culture so `config get` output round-trips through `config set`. `SimCommand`: same invariant parse. Int parsing left as-is (no culture ambiguity for plain integers). BuildId → 260610.15. Build: Debug, 0 errors.
