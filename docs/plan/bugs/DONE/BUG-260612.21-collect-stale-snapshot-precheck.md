# BUG-260612.21: Collect work loop — add Closed/MarkedForClose pre-check against stale snapshot entries

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260612.1 #L5 — `NanobotSystem.Collecting.cs:35-72`, `NanobotSystem.Scanning.cs:1278-1284`

## Description
Hardening follow-up to BUG-260610.22: a background scan swap mid-loop can replace `State.PossibleFloatingTargets` with fresh `TargetEntityData` instances built from a seconds-old cluster result, re-listing entities that were just emptied/removed; `Ignore` writes land on orphaned objects. All consequences verified bounded (re-detection next pass, no duplication — engine close is synchronous and main-thread), worst case a wasted re-processing pass plus one spurious sync.

## Root Cause
Snapshot processed outside the lock can outlive a list swap (inherent to the .22 design; engine guards make it safe).

## Fix
Cheap belt-and-braces: skip entries whose `Entity.MarkedForClose || Entity.Closed` at the top of the work loop.

**Resolution:** commit 5f9466c (BuildId 260612.9) on `fix/v2.5.6` - collect work loop skips entities whose Closed/MarkedForClose flipped since the under-lock pick (stale snapshot after a mid-loop scan swap). Build: Debug, 0 errors.
