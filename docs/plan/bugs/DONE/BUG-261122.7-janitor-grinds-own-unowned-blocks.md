# BUG-261122.7: Grind janitor (NoOwnership) grinds unowned blocks the BaR owner built — own hulls are ground instead of welded

## Status: Fixed
## Severity: High
## Version: v2.5.6 (also v2.5.5)
## Found In: in-game harness, first full run 2026-11-22 (S06, S08 failed: `welded=0`, `ServerDoWeld.calls=0`, `assignmentsPeak` 40/262, `grindBudgetPeak=1`, S08 `weldTargetsPeak=0`); likely GitHub #137 (jjjr2062, closed 2026-05-14 with janitor switched off as workaround, root cause never found) — `NanobotSystem.Scanning.Block.cs:43-58` (grind checked before weld), `:372` (janitor NoOwnership), `NanobotSystem.State.cs:112-122` (weld side)

## Description
A grid that has no owner — armor only, or functional blocks not yet past their ownership integrity — reads
`NoOwnership` for every block. The default janitor setting is `Enemies | NoOwnership`
(`SyncModSettingsWelder.cs:150`), and `AsyncAddBlockIfTarget` asks the grind check first: a block taken as a
grind target is never considered for welding. So a player's own armor-only hull, or a fresh grid in range of a
BaR, is ground down instead of repaired.

The weld side already handles this: `IsRelationAllowed4Welding` treats a `NoOwnership` block as the BaR owner's
when `BuiltBy` is the owner or a faction member ("freshly placed construction sites", "avoids welding derelict/NPC
grids"). The grind side has no such check, so the two sides disagree about the same block.

## Steps to Reproduce
1. Survival, default BaR settings (janitor `NoOwnership` on), BoundingBox mode.
2. Next to it, place a separate grid of a few armor blocks (no functional block), damage them.
3. The BaR grinds them away. Harness: `/nanobars test run S06` or `S08` (armor-only target grids built by the
   caller) → `welded=0`.

## Root Cause
The janitor `NoOwnership` rule looks at grid ownership only, not at who built the block.

## Fix
Fixed in BuildId 261122.7 (owner decision 2026-11-22: mirror the weld rule). `IsBuiltByOwnerOrFaction`
(`NanobotSystem.State.cs`) is shared by `IsRelationAllowed4Welding` and the janitor NoOwnership branch in
`AsyncAddBlockIfGrindTarget` (`NanobotSystem.Scanning.Block.cs`): an unowned block whose `BuiltBy` is the BaR owner
or a faction member is not a janitor target. Grind colour still grinds such blocks on purpose.
Verified in game (01_211_018, session `…172924`): S06 and S08 (armor-only grids built by the caller) now weld
40/40 and 1000/1000; S04 (derelict, BuiltBy 0) still razed. Unit: `JanitorOwnershipTests`. New harness S17
(ownership matrix) and S18 (rotor subgrid) cover it further.

## Scenario
SCN-GRIND-001 (new step: player-built armor-only grid in range with janitor `NoOwnership` → welded, not ground);
harness S06/S08 must pass unchanged.
