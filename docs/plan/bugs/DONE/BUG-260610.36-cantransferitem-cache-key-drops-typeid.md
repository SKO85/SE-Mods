# BUG-260610.36: InventoryHelper.CanTransferItemToCached cache key drops TypeId — Ore/Ingot collisions (currently unused)

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `Helpers/InventoryHelper.cs:79`

## Description
`TransferKey` uses only `componentId.SubtypeId.GetHashCode()`. `MyObjectBuilder_Ore/"Stone"` and `MyObjectBuilder_Ingot/"Stone"` (likewise Iron, etc.) produce identical keys, so a conveyor sorter that whitelists ingots but blocks ore would poison the cache for 60 s with the wrong answer. Grep shows no current callers — the only match is the definition itself — so this is latent dead code.

## Root Cause
Cache key omits `TypeId`.

## Fix
Either delete the unused method or include `componentId.TypeId` in the key before anyone adopts it.

**Resolution:** commit 132a435 (BuildId 260610.25) on `fix/v2.5.6` - deleted the dead TransferKey struct, TransferCache, TransferCacheCount and CanTransferItemToCached (zero callers, broken key); InventoryHelper.Cleanup no longer touches it. Build: Debug, 0 errors.
