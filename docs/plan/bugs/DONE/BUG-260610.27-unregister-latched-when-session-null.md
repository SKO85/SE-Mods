# BUG-260610.27: SafeZoneHandler/DamageHandler Unregister latch _registered=true forever if Session is null at unload

## Status: Fixed
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `Handlers/SafeZoneHandler.cs:136-153`, `Handlers/DamageHandler.cs:41-51`

## Description
Both `Unregister()` methods early-return when `MyAPIGateway.Session == null` **without** resetting `_registered`. If the session reference is already gone during `UnloadData` (ordering is engine-version dependent), the next world's `Register()` no-ops:

- SafeZoneHandler gets no entity events and no zone seeding — and its static `Zones` dictionary (holding `MySafeZone` entity refs from the dead world) is never cleared, compounding BUG-260610.11;
- DamageHandler never registers → BaR weld damage hurts characters in the new world.

## Root Cause
Flag reset and collection clear are gated behind the Session-dependent unsubscribe.

## Fix
Commit 901f0b8 on `fix/v2.5.6`.

- `SafeZoneHandler.Unregister`: the null-Session early return removed; only the event unsubscribe is conditional on a live server Session (the entity list dies with the session anyway). `Zones` + the three TTL caches are cleared and `_registered` reset unconditionally.
- `DamageHandler.Unregister`: body reduced to the unconditional `_registered = false` (SE has no damage-handler unregister API; the flag only exists to allow re-registration in the next world, so nothing should gate it).
