# BUG-260610.26: MethodProfiler stop/write race truncates session log files and leaks an open writer

## Status: Fixed
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `Profiling/MethodProfiler.cs:474-501, 739-757`

## Description
`StopAndLog` checks `IsEnabled` **outside** `_syncRoot`, then proceeds to `Write()` → `GetOrCreateWriter()`. If `StopSession()`/`TickAutoStop()` runs concurrently (background scan workers call `StopAndLog`; stop runs on the main thread), the in-flight call can reach `GetOrCreateWriter` after `CloseInternal()` cleared `_writers`. It then calls `MyAPIGateway.Utilities.WriteFileInLocalStorage(fileName, ...)` with the same session-prefixed filename, which opens-for-write and **truncates** the per-method log that was just finalized — destroying that method's session data. The orphan writer also stays open in `_writers` until the next `StartSession`/`Close`.

Related (lower priority): while profiling is running, every instrumented call from every thread funnels through the single global `_syncRoot` lock in `UpdateAggregate` (:503-535), serializing the main thread against 4–10 scan workers and skewing measurements. The disabled path is clean (no locks/allocations).

## Root Cause
Enabled-check and writer creation not atomic with session stop.

## Fix
Re-check `_isRunning` inside the `_syncRoot` block of `GetOrCreateWriter` and return null if stopped (callers already tolerate null).

**Resolution:** commit e777c09 (BuildId 260610.35) on `fix/v2.5.6` - GetOrCreateWriter re-checks _isRunning inside _syncRoot and returns null after StopSession/CloseInternal - no truncated session logs, no leaked writer; Write() already tolerates a null writer. Build: Debug, 0 errors.
