# BUG-260610.32: Lock-on assignment refresh ignores AssignToSystem failure (welding)

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `NanobotSystem.Welding.cs:221-226`

## Description
The lock-on refresh discards the `AssignToSystem` return value. If the TTL expired and another BaR claimed the block earlier in the same tick (stagger), both BaRs weld the same block until one finishes. Wasted duplicate work only, bounded by `AssignmentTtlSeconds`; the grind path handles the analogous race explicitly (`Grinding.cs:155-165`).

## Root Cause
Return value ignored on the weld lock-on refresh path.

## Fix
On refresh failure, release the lock-on and continue the picker loop (mirror the grind path).

**Resolution:** commit 45c61ef (BuildId 260610.21) on `fix/v2.5.6` - weld lock-on refresh now checks the AssignToSystem return value; on a lost claim race it drops the lock-on, sets lookingForNext and continues the picker (mirrors the grind path; no release - the claim belongs to the other BaR). Build: Debug, 0 errors.
