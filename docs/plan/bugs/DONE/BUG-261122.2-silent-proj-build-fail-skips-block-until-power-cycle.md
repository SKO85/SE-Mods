# BUG-261122.2: A projected block that silently fails to build 3 times is skipped until the BaR is power-cycled

## Status: Fixed
## Severity: High
## Version: v2.5.6
## Found In: GitHub #150 (Rl-Real45: "randomly stops welding projections; turning the grid off and on helps for a short while") — `NanobotSystem.Welding.cs:744-765` (BUG-120 promotion), `:467-472` (`Weldable` skip), `NanobotSystem.Init.cs:186` (cleared only on enabled change), `:516-525` (owner change)

## Description
BUG-120 moves a projected block into `_BrokenProjBuildKeys` after `PROJ_BUILD_MAX_SILENT_FAILS` (3) builds
that left no block, assuming "DLC missing". The skip never expires: only switching the BaR off/on or an owner
change clears it. Every other silent rejection gets the same permanent treatment — since 1.211.018 that is the
builder-inventory check (BUG-261122.1), and `BuildInternal` now also checks world limits and the RPC sender.
A temporary condition therefore turns into "the BaR ignores this projection" with no visible reason, which is
exactly the #150 symptom and its off/on workaround (`_onEnabledChanged` clears the set).

BUG-261122.1 removes the main cause, but the failure mode stays for any future or transient rejection.

## Steps to Reproduce
1. Game 1.211.018, survival, current code: let a BaR attempt a projection with an empty block inventory.
2. After 3 attempts per block the blocks stay in `Blocks to build` but are never tried again.
3. Switch the BaR off and on → it builds a few, then stops again.

## Root Cause
Permanent skip designed for one cause (DLC), applied to every silent rejection.

## Fix
Fixed in BuildId 261122.2 — owner picked (a) + (b):
- (a) Expiring skip: promotion writes `_ProjBuildSkipUntil[key] = now + 5 min` (`NanobotSystem.cs:294`,
  `NanobotSystem.Welding.cs:842`); `IsProjBuildSkipped` (:530) checks it in `Weldable`; after expiry the block
  gets a fresh 3 strikes. NRE skips (BUG-115, `_BrokenProjBuildKeys`) stay permanent — they log at Error and
  would repeat every expiry. Off/on and owner change still clear everything.
- (b) Visible count: `RefreshProjBuildSkips` (:539, every weld tick, purges expired keys) publishes the count as
  `SyncBlockState.ProjectedBlocksSkipped` (ProtoMember 24, never used before; in the state fingerprint) so DS
  clients see it; terminal info line `Info_ProjectedSkipped` ("Projected blocks skipped: N (retried
  automatically)") in all five languages.
- Test: `ProjectedBuildComponentTests.SilentFailSkip_Expires_NreSkipStays_CountIsPublished`.

## Scenario
SCN-WELD-002 (variant C/E: skipped block is retried after the expiry, and the skip count is visible).
