# BUG-260827.2: SE engine refuses adds to the detached transport inventory — welding fully starved

## Status: Fixed
## Severity: Critical
## Version: v2.5.6
## Found In: In-game no-weld report; diagnosed via profiler + PICKDIAG log (BuildId 260827.1-.3)

## Description
BaRs stopped welding entirely: target chosen every tick, components pulled from cargo
into the welder inventory (12-17 stacks/tick — hoarding + lag), but the welder→transport
hand-off (`ServerPickFromWelder`) moved nothing, so `ServerDoWeld` failed on missing
components, blocks cycled through the 15 s failure cooldown, and push-immediately bounced
the hoarded components back to cargo (endless item ping-pong).

PICKDIAG evidence: component present in the welder (`matched=1`), volume budget healthy
(`remVol=1.56`), transport EMPTY (`transportVol=0`, max 15.6 m³) — yet
`_TransportInventory.CanItemsBeAdded(1, Component/InteriorPlate)` returned **false**.
The BUG-260612.2 destruction guard trusted that answer and vetoed every pick.

## Root Cause
Engine behavior change in the current SE build: `MyInventory.CanItemsBeAdded` returns
false for the mod's detached (entity-less) transport inventory, apparently due to an
uninitialized mass constraint in the short `MyInventory(float, Vector3, MyInventoryFlags)`
constructor. Not caused by the 260824.x fix batch — that batch merely shipped alongside
the first in-game test since June.

## Fix
- `NanobotSystem.Init.cs`: transport inventory constructed with explicit unlimited
  maxMass — `new MyInventory(vol, float.MaxValue, Vector3.MaxValue, CanSend)`.
- `NanobotSystem.Welding.cs` (`ServerPickFromWelder`): stop trusting `CanItemsBeAdded` on
  the detached inventory — check real volume headroom directly, then VERIFY the add
  landed (GetItemAmount before/after) and return any remainder to the welder so no items
  are destroyed (BUG-260612.2 concern preserved). `TryPullFromSource` oversized gate uses
  the direct headroom check too.
- Diagnostic build ids 260827.2-.4; final fix BuildId 260827.5.
- Note: `EmptyBlockInventories` (grind loot) and collecting also target this inventory
  via engine `TransferItemFrom`/`AddMaxItems`; the constructor fix should heal those
  paths as well — verify in-game when grinding is next tested.
