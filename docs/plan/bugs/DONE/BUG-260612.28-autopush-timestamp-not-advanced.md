# BUG-260612.28: ServerTryPushInventory re-walks the welder inventory every tick when nothing is eligible

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260612.1 #L12 — `NanobotSystem.Inventory.cs:110`

## Description
`_TryAutoPushInventoryLast` is only advanced inside `if (eligible)`. When the welder holds only item types whose push flags are disabled, the 5 s interval gate never re-arms and the method snapshots (`GetItems`) and walks the inventory every tick (bounded by the 5 ms budget). CPU waste only; no correctness impact.

## Root Cause
Interval timestamp tied to eligibility instead of to the attempt.

## Fix
Advance `_TryAutoPushInventoryLast` whenever the walk runs (or at least when it completes with zero eligible items).

**Resolution:** commit ea784a0 (BuildId 260612.10) on `fix/v2.5.6` - _TryAutoPushInventoryLast advances whenever the push walk runs, not only when an item was eligible — all-ineligible inventories no longer re-walk every tick. Build: Debug, 0 errors.
