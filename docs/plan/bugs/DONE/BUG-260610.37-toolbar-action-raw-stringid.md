# BUG-260610.37: On/off toolbar action names render raw MyStringId keys for vanilla texts

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `Terminal/OnOffSwitches.cs:48-49, 59-60, 70-71`

## Description
`string.Format("{0} {1}/{2}", name, onoffSwitch.OnText, onoffSwitch.OffText)` calls `MyStringId.ToString()`, which returns the key. For mod-local `Texts.*` ids that happens to be the localized text (built via `GetOrCompute(localizedString)`), but for `MySpaceTexts.SwitchText_On/Off` it yields literal `"SwitchText_On"`/`"SwitchText_Off"` in toolbar-config action names. Cosmetic.

## Root Cause
`MyStringId` formatted directly instead of resolved through `MyTexts`.

## Fix
Use `MyTexts.Get(...)` (or `MyTexts.GetString`) for the on/off text in the action name format.

**Resolution:** commit 10fcb8d (BuildId 260610.26) on `fix/v2.5.6` - action names resolve OnText/OffText via MyTexts.GetString - vanilla ids render localized text, mod-local GetOrCompute ids fall back to their (already localized) key. Build: Debug, 0 errors.
