# BUG-260612.38: ScriptControllFixed unregisters the entire scripting API, including read-only properties

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: Script audit 2026-06-12 — `Terminal.cs:529-581`

## Description
The whole scripting-properties block — `WeldPriorityList`/`GrindPriorityList`/
`ComponentClassList` and their get/set delegates, `MissingComponents`,
`PossibleTargets`/`PossibleGrindTargets`/`PossibleCollectTargets`,
`CurrentTarget`/`CurrentGrindTarget`, `CurrentPickedTarget`/`CurrentPickedGrindTarget`,
`ProductionBlock.EnsureQueued`, `Inventory.NeededComponents4Blueprint` — is
nested inside `if (!Mod.Settings.Welder.ScriptControllFixed)` together with the
ScriptControlled switch and the Reset button.

If the intent of `ScriptControllFixed` is "scripts may not drive the BaR", the
read-only informational properties (target lists, missing components, current
targets) and the assembler-queue helper could stay registered; only
`ScriptControlled` and the picked-target setters need to go. As-is, the lockdown
also breaks purely informational LCD scripts (and crashes the companion script —
BUG-260612.36/.37). The control properties registered elsewhere (Mode, WorkMode,
colors, area, janitor switches) remain available regardless, so the lockdown is
partial either way.

## Root Cause
Likely an accident of brace nesting inherited from the original mod — the
"=========== Properties ============" section sits inside the script-control `if`.

## Fix
Decide intent. If lockdown should only block script *control*: move the
read-only property registrations (and `EnsureQueued`/`NeededComponents4Blueprint`)
out of the `if`, and register `CurrentPickedTarget`/`CurrentPickedGrindTarget`
without setters when fixed. If full lockdown is intended: document it and rely on
BUG-260612.36/.37 making the companion script degrade gracefully.

## Resolution
Commit fbaa70d (BuildId 260612.14) on `fix/v2.5.6` — lockdown now blocks script
*control* only. The Properties block moved out of the `if (!ScriptControllFixed)`
in `Terminal.cs`: read-only properties (priority lists, Get* delegates,
MissingComponents, target lists, CurrentTarget/CurrentGrindTarget, EnsureQueued,
NeededComponents4Blueprint) register unconditionally; mutators (Set* delegates)
register only when script control is allowed; `CurrentPickedTarget`/
`CurrentPickedGrindTarget` gained a `readOnly` parameter in `Properties.cs` and
register without setters when fixed. The ScriptControlled switch/property and the
Reset button remain inside the `if`. Build: Debug, 0 errors.
