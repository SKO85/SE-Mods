# BUG-260824.10: EnsureQueued exposed as "read-only" under ScriptControllFixed but mutates assembler queues

## Status: Fixed
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-260824.1 — `Terminal.cs:594`, `Utils/UtilsProductionBlock.cs:105,117`

## Description
BUG-260612.38 moved `ProductionBlockEnsureQueued` out of the `if (!ScriptControllFixed)` gate
as a "read-only" property, but `UtilsProductionBlock.EnsureQueued` mutates game state
(`AddQueueItem`, no ownership check on the caller-supplied assembler entity ids).

Failure: admin sets `ScriptControllFixed=true` to keep the scripting API read-only (the
in-code invariant at `Terminal.cs:543-546` says exactly that). Any programmable-block script
fetches `BuildAndRepair.ProductionBlock.EnsureQueued` from any BaR and queues arbitrary
blueprint amounts into assemblers resolved by caller-supplied entity ids — a mutation the
setting previously blocked. BUG-260612.38's Resolution mislabels EnsureQueued as read-only.

## Root Cause
Mutation-capable delegate misclassified as read-only during the lockdown refactor.

## Fix
`Properties.ProductionBlockEnsureQueued()` moved behind the `scriptControlAllowed`
gate; the pure-read `InventoryNeededComponents4Blueprint` stays always-registered.
Companion script already guards the missing property (returns -3). Commit 81561a9,
BuildId 260824.2. File: `Terminal.cs`.
