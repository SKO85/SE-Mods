# BUG-260609.3: Stale full-inventory pick guard aborts a pickup that push just made resumable

## Status: Fixed
## Severity: Low
## Version: v2.5.5
## Found In: Codex PR review — `NanobotSystem.Operations.cs`

## Description
In `ServerTryWeldingGrindingCollecting`, the full-inventory-while-picking guard
was captured once on entry:

```csharp
var isFullInventoryAndPicking = State.InventoryFull && State.CurrentTransportIsPick;
```

In the `ready` path it is then consumed *after* two calls that can mutate
`State.InventoryFull` on the same tick:

1. `ServerTryPushInventory()` (`Operations.cs:82`) pushes items out of the
   welder's own inventory (`NanobotSystem.Inventory.cs:109`,
   `welderInventory.PushComponents(...)`), draining it.
2. `CheckAndUpdateInventoryFull()` (`Operations.cs:86`) clears
   `State.InventoryFull` once the welder drops below 90% of max
   (`Operations.cs:440-444`).

The branch at the old `Operations.cs:88` still read the stale entry snapshot, so
when auto-push freed space on the same tick the inventory filled, the active
grind/collect pickup was aborted (`CurrentTransportTarget`/`CurrentTransportStartTime`
cleared) instead of being allowed to resume via `IsTransportRunning(...)`.

## Steps to Reproduce
1. Enable a Push* flag on a BaR and have it grind/collect into the welder until
   `State.InventoryFull` trips while a pick transport is active
   (`CurrentTransportIsPick`).
2. On the tick where the auto-push drains the welder below 90% (clearing
   `InventoryFull`), observe the in-progress pickup is dropped rather than
   resumed.

## Expected behavior
Once space is freed and `InventoryFull` is cleared, the active pickup should
continue.

## Actual behavior
The pickup is aborted because the guard used the entry-time snapshot, which was
still `true`.

## Root Cause
`isFullInventoryAndPicking` was snapshotted on entry (`Operations.cs:49`) but
consumed after `ServerTryPushInventory()` and `CheckAndUpdateInventoryFull()`
had already mutated `State.InventoryFull` in the `ready` path.

## Fix
- `NanobotSystem.Operations.cs` — in the `ready` path, re-read current state
  immediately before the guard: `if (State.InventoryFull && State.CurrentTransportIsPick)`.
  `CurrentTransportIsPick` is untouched by push, so re-reading `InventoryFull` is
  sufficient. The not-ready `else` path (`Operations.cs:164`) still uses the
  entry snapshot — correct there, since nothing mutates `InventoryFull` before
  it on that path.
- `Constants.cs` — BuildId bumped to `260609.3`.

## Notes
Low severity: only triggers with auto-push enabled and only when the drain
crosses the 90% hysteresis on the same tick. Effect is a one-tick stutter (the
transport is dropped, then re-acquired on a later scan), not a permanent stall.

Related: BUG-260526.1 (InventoryFull clear-on-drain), BUG-015 (full-welder
detection after push).
