# BUG-260610.9: _ActiveWorkingEffects counter leaks on particle-creation failure — effects can become permanently disabled

## Status: Fixed
## Severity: High
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `Effects.cs:158-165`

## Description
In `SetWorkingEffects`, `_ActiveWorkingEffects++` executes **before** `MyParticlesManager.TryCreateParticleEffect(...)`. If creation fails (`_ParticleEffectWorking1` stays null — particle pool exhausted or definition missing), the increment is never undone: the decrement (:141-146 and `Close()`) only fires when `_ParticleEffectWorking1 != null`. The static counter drifts upward monotonically; once it reaches `MaxWorkingEffects` (150), no BaR on the client can show welding/grinding particles or lights again for the rest of the session. `SetTransportEffects` (:370-379) was already fixed to increment only on success — the same fix is missing here.

## Root Cause
Increment-before-create with decrement gated on the created object.

## Fix
Commit be22056 on `fix/v2.5.6`. `_ActiveWorkingEffects++` moved inside the `if (_ParticleEffectWorking1 != null)` block after `TryCreateParticleEffect`, mirroring `SetTransportEffects`. BuildId → 260610.4. Build: Debug, 0 errors.
