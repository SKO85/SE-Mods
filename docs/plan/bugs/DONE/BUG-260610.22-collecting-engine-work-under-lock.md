# BUG-260610.22: Collecting performs engine inventory transfers and entity deletion while holding the target-list lock

## Status: Fixed
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `NanobotSystem.Collecting.cs:30-50`

## Description
`ServerTryCollectingFloatingTargets` holds `lock (State.PossibleFloatingTargets)` across `ServerDoCollectFloating`, which does `EmptyFloatingObject`/`EmptyBlockInventories` (engine `TransferItemFrom`/`AddItems` calls, ms-scale), `MyFloatingObjects.RemoveFloatingObject`, `target.Delete()` for bot corpses, and `ServerEmptyTransportInventory`. The background scan worker blocks on this exact lock when publishing results (`Scanning.cs:1219-1224`), so a slow collect tick stalls a scan worker (pool of 4) — the same contention BUG-135/BUG-137 eliminated for the weld and grind loops.

## Root Cause
Engine work inside the shared-list lock.

## Fix
Pick targets under the lock (snapshot what to collect), then do the inventory/engine work outside the lock — same pattern as the weld/grind loops.

**Resolution:** commit 030f674 (BuildId 260610.33) on `fix/v2.5.6` - targets picked under the lock into the reusable _TempCollectTargets buffer; ServerDoCollectFloating (engine inventory transfers / entity deletion) runs outside; one ChangeHash under the lock afterwards; buffer cleared so entity refs are not pinned. Build: Debug, 0 errors.
