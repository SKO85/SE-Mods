# BUG-260610.15: Background workers swallow all exceptions without logging; pending queue survives unload

## Status: Fixed
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `Managers/BackgroundTaskQueue.cs:84`, `Mod.cs:448-456`, `NanobotSystem.Scanning.cs:573-598`

## Description
Two related problems:

1. `BackgroundTaskQueue.WorkerLoop` wraps task execution in a bare `catch { }` with zero logging. Game entities can close mid-scan on the background thread; `GridIntegerToWorld`/`IsInRange` in the filter/sort phase can throw. Such an exception aborts the scan after the expensive work, may skip `cluster.SetResult` and the State swap, and vanishes without a log line. Recurring failures (e.g. a systematically bad candidate) are completely invisible — State lists silently stay stale while `_lastFullScanTime` still advances (finally at Scanning.cs:611), so the saturated-skip can then suppress retries. The scan publish/apply phase (`Scanning.cs:573-598`) has no catch of its own (`ApplyClusterResultToSelf` is try/finally only).
2. `Mod.UnloadData` waits at most 1 s for `RunningWorkers <= 0`, then tears down state regardless. Workers that outlive the timeout keep executing against state being disposed and can repopulate `SharedGridBlockCache`/`SharedEntityCache` after the unload-clear with dead-world data. The pending `_queue` is never purged on unload — leftover actions run in the next world's first worker spawn, touching closed entities.

## Root Cause
Silent catch; no shutdown signal or queue purge on unload.

## Fix
Log (throttled) in the worker catch; purge the pending queue in `UnloadData`; add a static shutting-down flag that workers check before executing each action.

**Resolution:** commit 219b5b1 (BuildId 260610.32) on `fix/v2.5.6` - worker catch now logs at Error level; new BeginShutdown() (called first in Mod.UnloadData) purges the queue and stops workers picking up actions; Reset() at the end of UnloadData re-arms for the next session. Build: Debug, 0 errors.
