# BUG-260610.42: MaximumOffset range differs between config command and model clamp

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: docs audit (2026-06-10) — `Chat/Commands/ConfigCommand.cs:43-45`, `Models/SyncModSettings.cs:325-328`

## Description
`/nanobars config set MaximumOffset` caps the value at 1000, but the model clamp (`ValidateAndClamp`) allows up to `NanobotSystem.WELDER_OFFSET_MAX_IN_M` = 2000 — so a hand-edited `ModSettings.xml` can legitimately hold 1001-2000, a value the chat command then refuses to set back. Same shape as BUG-260610.30 (Range), just in the opposite direction (command stricter than model instead of looser), so there is no server/client divergence — only an inconsistent admin surface.

## Root Cause
Hardcoded command bound diverged from the model constant.

## Fix
Use `NanobotSystem.WELDER_OFFSET_MAX_IN_M` as the command's max (mirror of the BUG-260610.30 fix).

**Resolution:** commit f20bc90 (BuildId 260610.37) on `fix/v2.5.6` - ConfigCommand MaximumOffset max now uses NanobotSystem.WELDER_OFFSET_MAX_IN_M (2000), mirroring the BUG-260610.30 Range fix. Build: Debug, 0 errors.
