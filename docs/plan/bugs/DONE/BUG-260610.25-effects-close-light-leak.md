# BUG-260610.25: Effects.Close() never removes the light from MyLights — renderer light leak on block close

## Status: Fixed
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `Effects.cs:438-443`

## Description
`SetWorkingEffects` tears down lights correctly with `MyLights.RemoveLight(_LightEffect)` (:150), but `Close()` only does `_LightEffect.Clear(); _LightEffect.LightOn = false;` and drops the reference. The light object stays registered in the engine's (pooled) light collection — the slot is never returned. Every BaR block closed while actively welding/grinding (common when BaRs grind each other's grids, or on grid deletion) leaks one render light. `Init.Close()` calls `_Effects.UpdateEffects(this)` first, which may remove it via a state transition, but that is not guaranteed (depends on `GetWorkingState()` and the camera-distance branch).

## Root Cause
Close path uses a different (incomplete) teardown than the state-transition path.

## Fix
Commit 6b55088 on `fix/v2.5.6`. `Effects.Close()` now calls `MyLights.RemoveLight(_LightEffect)` and nulls the reference — the same teardown `SetWorkingEffects` uses — instead of `Clear()` + `LightOn = false`, which left the pooled slot registered forever.
