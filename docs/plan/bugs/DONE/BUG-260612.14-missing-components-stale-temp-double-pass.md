# BUG-260612.14: ServerFindMissingComponents — stale _TempMissingComponents causes duplicate pull pass and doubled missing-component reporting for projected blocks

## Status: Fixed
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-260612.1 #M7 — `NanobotSystem.Welding.cs:839-908`

## Description
The projected-block branches fill `_TempMissingComponents` with the creation component and pull. The dictionary is only cleared/refilled in the `picked == true` non-skeleton branch; in the other cases it still holds the creation component when the trailing `if (_TempMissingComponents.Count > 0)` runs a SECOND `ServerFindMissingComponents` pass with the same entry. Consequences: in skeleton/ignore-color mode, a redundant full welder-pick + source walk every tick (and a needless extra component pulled when available); in normal mode with the component unavailable, `AddToMissingComponents` runs twice → terminal panel and clients show 2× the actual need.

## Root Cause
Phase bookkeeping: temp dictionary reused across phases without clearing on all paths.

## Fix
Clear (or branch around) `_TempMissingComponents` after the projected-block pull on the skeleton/ignore-color and `picked == false` paths so the trailing pass only runs for the non-projected flow it was written for.

**Resolution:** commit 542b90b (BuildId 260612.13) on `fix/v2.5.6` - _TempMissingComponents cleared after the skeleton/ignore-color pull and on the picked==false projected path — the trailing pass no longer re-pulls every tick nor double-reports the creation component (terminal showed 2x the need).
