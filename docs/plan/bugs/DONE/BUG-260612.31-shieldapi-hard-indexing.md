# BUG-260612.31: ShieldApi.ApiLoad hard-indexes delegate keys — one missing key permanently bricks shield protection

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260612.1 #L15 — `Mods/ShieldApi.cs:114-162, 70`

## Description
`ApiLoad` sets `_apiInit = true` before ~45 dictionary indexer lookups; any `KeyNotFoundException` (older/forked DefenseShields missing one key) leaves `IsReady` false forever, `HandleMessage` dead (early-return on `_apiInit`), and the exception propagates into SE's mod-message dispatch — zero shield protection with one obscure log line. The mod only uses `IsBlockProtected` and `ProtectedByShield`.

## Root Cause
Official DS client snippet assumes exact version parity; readiness flag set before the fallible work.

## Fix
Use `TryGetValue` per key (null delegates for missing optional ones), require only the two delegates the mod actually calls for `IsReady`, and set `_apiInit` only on success.

**Resolution:** commit deb870d (BuildId 260612.12) on `fix/v2.5.6` - ApiLoad uses a TryGetValue helper for all ~45 delegates (missing keys resolve to null wrappers), _apiInit set only after the load, and IsReady requires only the two delegates the mod calls (IsBlockProtected, ProtectedByShield) — DS version skew can no longer brick shield protection or throw into SE dispatch.
