# BUG-261122.19: A safe zone that forbids welding also stops building projections

## Status: Fixed
## Severity: Medium
## Version: v2.5.6 (regression from BUG-260612.13, not in a release)
## Found In: Codex review on PR #152 (NanobotSystem.Operations.cs MultiWeld)

## Description
BUG-260612.13 added an execution-time gate `if (!State.SafeZoneAllowsWelding) return;` before the weld loop. The scan
checks projected targets against `SafeZoneAllowsBuildingProjections` and real blocks against `SafeZoneAllowsWelding`,
so in a zone that allows building projections but not welding, projected targets are found and then never built
(also in WeldSkeleton mode).

## Fix
Gate per operation: MultiWeld returns only when the zone allows neither; the chosen target is checked with
`IsWeldTargetAllowedByZone` (projected -> BuildingProjections, real -> Welding) next to the BUG-261122.16 area check
(release, drop from the list). A placed projection is not welded further (ServerDoWeld welds real blocks only, and the
next scan excludes it while welding is forbidden).

## Scenario
SCN-ZONE-001 — ingame:S85 (zone without Welding, with BuildingProjections: 10 projected blocks placed, none welded,
SteelPlate conserved). S39 (no welding) and S42 (no building projections) unchanged.

## Resolution
`MultiWeld` gate + `IsWeldTargetAllowedByZone` in ServerTryWelding. BuildId 261122.34 (S85 checks refined in 261122.36).
Verified in game, BuildId 261122.36 (creative tools and "ignore safe zones" off): S85 — 10 placed, 0 welded; SteelPlate
conserved (rig 750 + stockpiles 240 + 10 mounted: the projection build stockpiles the BaR's ready components).
S03 (10 built + welded, 25 each), S39 (no welding: nothing welded), S42 (no building projections: nothing built) green.
