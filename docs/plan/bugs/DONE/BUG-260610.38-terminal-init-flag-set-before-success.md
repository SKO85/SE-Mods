# BUG-260610.38: Terminal.InitializeControls marks itself initialized before the work succeeds

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `Terminal.cs:149-150`

## Description
`CustomControlsInit = true` is set before the `try`; if control creation throws midway (caught at :583), the terminal is left permanently half-built for the session with no retry. Low likelihood, but cheap to make self-healing.

## Root Cause
Init flag set optimistically.

## Fix
Set the flag at the end of successful initialization (or reset it in the `catch`).

**Resolution:** commit 1f5621e (BuildId 260610.27) on `fix/v2.5.6` - catch now unsubscribes CustomControlGetter, clears CustomControls and resets CustomControlsInit so the next init attempt starts clean; engine-side controls already added are reused on retry. Build: Debug, 0 errors.
