# BUG-261122.18: Ignore-color projections counted with their full bill in the missing list

## Status: Fixed
## Severity: Low
## Version: v2.5.6 (regression from BUG-260824.2, not in a release)
## Found In: Codex review on PR #152 (NanobotSystem.Welding.cs missing-components aggregate)

## Description
With Use Ignore Color on, a projected block in the ignore color is only placed (creation component) and not welded
further: the pull path asks for `IntegrityLevel.Create`, ServerDoWeld skips welding on `hasIgnoreColor`. The aggregate
used the BaR-wide level (Functional / Complete) for every target, so these blocks added their full bill (armor: 25
SteelPlate instead of 1) and the companion script queued production that is never used.

## Fix
Per target in the aggregate: projected + ignore color on + color match -> `IntegrityLevel.Create`, the same rule as
the pull path. One flag test + color pack per projected target, no allocation.

## Scenario
SCN-WELD-005 — unit:MissingComponentsAggregateTests.IgnoreColorProjection_CountsTheCreationComponentOnly (fails
without the fix: 50 instead of 26).

## Resolution
Per-target level in `ServerTryRebuildMissingComponentsAggregate` phase 1. BuildId 261122.33.
