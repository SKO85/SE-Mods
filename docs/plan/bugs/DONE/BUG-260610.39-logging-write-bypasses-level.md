# BUG-260610.39: Logging.Write(string, params) bypasses the log level and flushes per line

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `Utils/Logging.cs:217-220, 240-250`

## Description
The `Write(string msg, params object[] args)` overload has no `LogLevel` gate, and `Write(string)` does `_Writer.Write(_Cache); _Writer.Flush();` — synchronous file I/O with a flush per line under a global lock, callable from the main thread. Current call sites of the ungated overload are rare init/error paths (`Mod.cs:325`, `HudHandler.cs:148`, `SyncModSettings.cs:499`, `SyncBlockSettings.cs:615`), so impact today is low — but any future caller assuming level filtering will silently produce per-frame main-thread disk writes. A trap, not a live regression.

## Root Cause
Convenience overload skips the level gate; per-line flush.

## Fix
Route the params overload through the level gate (or rename it to make "always writes" explicit); consider deferring flushes to the periodic maintenance tick.

**Resolution:** commit 6178937 (BuildId 260610.28) on `fix/v2.5.6` - level-less Write(string, params) overload routes through Write(Level.Error, ...); default LogLevel is Error so all existing call sites behave identically. Build: Debug, 0 errors.
