# BUG-260612.32: ShieldApi Compromised flag is set but never consumed

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260612.1 #L16 — `Mods/ShieldApi.cs:65-75`

## Description
When DefenseShields broadcasts "Compromised" (API integrity failure), the wrapper sets the flag but nothing reads it — the mod keeps invoking the delegates and `/nanobars mods` keeps reporting "Active".

## Root Cause
Flag wired in from the DS client snippet without a consumer.

## Fix
Honor it (treat Compromised as not-ready at the check sites / in `/nanobars mods`) or remove the property.

**Resolution:** commit deb870d (BuildId 260612.12) on `fix/v2.5.6` - Compromised is honored: the broadcast is processed even after init (was swallowed by the _apiInit early-return) and IsReady returns false while Compromised — all check sites and /nanobars mods react automatically. Build: Debug, 0 errors.
