# BUG-261023.10: Block data requests have no rate limit (DoS amplification)

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-261023.1 #10 — `Handlers/NetworkMessagingHandler.cs:106-129` (`ServerMsgBlockDataRequestReceived`)

## Description
Any client can request settings + full state (`GetTransmitFull`) for any BaR EntityId as often as it
likes; each request costs the server two serializations and two sends. A modified client can loop over all
EntityIds. (The read-only information exposure itself was accepted in BUG-260610.2.)

## Steps to Reproduce
Crafted client sending MSGID_BLOCK_DATAREQUEST in a loop.

## Root Cause
Rate limiting was added only to the settings message (BUG-260610.31).

## Fix
Implemented (BuildId 261023.6), `Handlers/NetworkMessagingHandler.cs`: per-(block, sender) window of
2 s (`DataRequestMinIntervalSeconds`, `NanobotSystem._lastDataRequestBySender`, mirrors the settings
limiter) — repeats are dropped before the two full serializations. **No per-sender global cap**: the
client sends exactly one request per BaR when it streams in and never retries, so a cap would leave
BaRs without settings/state for a player joining a big base. Remaining exposure (one reply per BaR per
2 s for a crafted client) is bounded and accepted. No unit test (handler needs the network stack).

## Scenario
SCN-NET-001 (repeat requests dropped)
