# BUG-260610.1: Session-relative static timers never reset on world unload — scans and periodic maintenance go dead

## Status: Fixed
## Severity: Critical
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `Mod.cs`, `Managers/PeriodicMaintenanceScheduler.cs`, `Handlers/GridOwnershipCacheHandler.cs`, `Handlers/FriendlyRelationsHandler.cs`

## Description
Static fields holding `MyAPIGateway.Session.ElapsedPlayTime` (or frame counter) values are never reset by `Mod.UnloadData()` (Mod.cs:441-503):

- `Mod.cs:240` `_LastSourcesAndTargetsUpdateTimer`, `Mod.cs:242` `_LastSyncModDataRequestSend`
- `PeriodicMaintenanceScheduler.cs` — all static `PeriodicTask.LastRun` fields (six tasks)
- `GridOwnershipCacheHandler.cs:30` `LastCheckTime`
- `FriendlyRelationsHandler.cs:38` `_LastDamageCleanup`
- `Mod.cs:97-98` `_cachedAutoStagger` / `_cachedAutoStaggerFrame`
- `Mod.cs:139` `SimSpeedOverride` (admin override leaks into the next world)

Worlds can be unloaded/loaded repeatedly in one game process. Loading a world whose play time is lower than the previous world's leaves every `now.Subtract(lastRun) >= interval` gate false until the new world's play time exceeds the old timestamp. Consequences: `RebuildSourcesAndTargetsTimer` (Mod.cs:618) never fires → cluster rebuild and all target/source scans never run → every BaR idles indefinitely; all periodic maintenance dead (ownership cache, safe-zone cleanup, TTL cleanups, assignment cleanup, friendly-relations rebuild, profiler flush); DS clients never re-send the settings request; auto-stagger frozen at the old world's value.

## Steps to Reproduce
1. Load world A, play for e.g. 1 hour (or load a long-running save).
2. Exit to menu (no game restart), load a fresh world B with BaRs.
3. BaRs never scan/weld; `/nanobars` maintenance-dependent behavior dead until B's play time exceeds A's.

## Root Cause
Statics persist across session unload/load; none of the session-relative timestamps are re-initialized.

## Fix
Commit 416b6a1 on `fix/v2.5.6`. Added `ResetSessionState()` methods and wired them into `Mod.UnloadData()` (after the shared-cache clears, wrapped in try/catch like the other teardown steps):

- `Mod.cs` — new private static `Mod.ResetSessionState()` resets `NowPlayTime` (also session-relative; feeds `TtlCache`/`GridOwnershipCacheHandler` timestamps), `_LastSourcesAndTargetsUpdateTimer`, `_LastSyncModDataRequestSend`, `_cachedAutoStagger` (-1) / `_cachedAutoStaggerFrame` (int.MinValue), `SimSpeedOverride` (null), then delegates to the three handlers below. Called from `UnloadData`.
- `Managers/PeriodicMaintenanceScheduler.cs` — `ResetSessionState()` sets all six `PeriodicTask.LastRun` fields to `TimeSpan.Zero`.
- `Handlers/GridOwnershipCacheHandler.cs` — `ResetSessionState()` sets `LastCheckTime = TimeSpan.Zero`.
- `Handlers/FriendlyRelationsHandler.cs` — `ResetSessionState()` sets `_LastDamageCleanup = TimeSpan.Zero`.

`PerTickBudget._lastTick` self-heals on first claim (verified in review) and `_nextStaggerSlot` is modulo-consumed, so neither needs resetting. BuildId → 260610.1. Build: Debug, 0 errors.
