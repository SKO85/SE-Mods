# BUG-260612.5: Enabling ShieldCheckEnabled at runtime yields zero protection until world restart

## Status: Fixed
## Severity: High
## Version: v2.5.6
## Found In: REVIEW-260612.1 #H5 — `Mod.cs:307-312`, `Chat/Commands/ConfigCommand.cs`

## Description
The `ShieldApi` instance is created only in `Mod.Init()` and only if `Settings.ShieldCheckEnabled` is already true. `/nanobars config set ShieldCheckEnabled true` (and `config reload` from XML) only flip the bool; nothing creates/loads the API afterward, and every check site requires `Mod.Shield != null` — so shield protection silently stays off until the world restarts, while `config list` shows it enabled. The only hint is `/nanobars mods` showing "Not detected", which wrongly implies DefenseShields isn't installed.

## Root Cause
API lifecycle bound to init-time setting value.

## Fix
Create + `Load()` the `ShieldApi` when the setting flips to true and `Mod.Shield == null` (in the config setter or `Mod.SettingsChanged`); optionally unload it when flipped off.

**Resolution:** commit 07b4588 (BuildId 260612.2) on `fix/v2.5.6` - Mod.SettingsChanged now creates + Loads the ShieldApi when ShieldCheckEnabled is true and Shield is null (mirrors Init) - config set/reload paths all call SettingsChanged, so runtime enabling works on server and clients without restart.
