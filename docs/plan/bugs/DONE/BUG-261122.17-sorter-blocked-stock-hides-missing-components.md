# BUG-261122.17: Stock behind a sorter hides missing components — the companion script stops queuing

## Status: Fixed
## Severity: Medium
## Version: v2.5.6 (regression from BUG-260824.2, not in a release)
## Found In: Codex review on PR #152 (NanobotSystem.Welding.cs SubtractInventoryFromAggregateNeed)

## Description
The missing-components aggregate subtracts the stock of every connected source. Sources are admitted by conveyor
connectivity (`IsConnectedTo`); a sorter that blacklists a component does not break that, it only makes the real pull
(`TransferItemFrom`) fail. Stock behind such a sorter therefore covers the need on paper, the BaR reports nothing
missing, the companion script queues nothing and the build stalls. v2.5.5 reported it (missing list came from failed
pulls).

## Fix
Only count a connected source's item when `CanTransferItemTo(welder inventory, item)` allows it. The BaR's own
welder / transport inventories are counted as before. One engine check per still-needed component kind per source,
once per 3 s pass, sliced and stopping when the need is covered.

## Scenario
SCN-WELD-005 — unit:MissingComponentsAggregateTests.SourceStockTheBarCannotPull_IsNotSubtracted; ingame:S84 (cargo
behind a blacklisting sorter: SteelPlate stays missing, the stock stays put).

## Resolution
`SubtractInventoryFromAggregateNeed(src, reachTo)`: sources pass the welder inventory, own inventories null.
