# BUG-260610.31: No rate limiting on client block-settings messages

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `Handlers/NetworkMessagingHandler.cs:267-273`

## Description
Each received `MsgBlockSettings` triggers a synchronous XML serialize to entity storage (`Settings.Save`) plus a `SendMessageToOthers` broadcast. The legitimate client gates sends on `IsTransmitNeeded()`'s 1 s timer, but the server applies no per-sender throttle — a client spamming this message gets free server CPU + N-client bandwidth amplification.

## Root Cause
Server trusts client-side throttling.

## Fix
Per-block (or per-sender) minimum interval on the server before persist/broadcast; coalesce rapid updates. Goes well with the BUG-260610.2 access check.

**Resolution:** commit cb308c2 (BuildId 260610.20) on `fix/v2.5.6` - 500 ms per-block server-side rate limit in MsgBlockSettingsReceived (new NanobotSystem._lastClientSettingsAppliedAt); legit clients send at most once per second so they are unaffected. Build: Debug, 0 errors.
