# BUG-260612.15: Own-shield gate covers off-grid autogrind only — color grind escapes it, info panel text overstates it

## Status: Fixed
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-260612.1 #M8 — `NanobotSystem.Scanning.Block.cs:276-281, 307-320`, `NanobotSystem.CustomInfo.cs:216-219`

## Description
The "my own grid is shielded" rejection sits inside the `if (autoGrind)` branch only. A BaR whose own grid is shielded can still color-grind blocks on other grids (only the target-side shield check applies) and weld off-grid freely. Meanwhile the info panel prints "Shields Active: Grinding disabled!" — wrong on two counts (own-grid grinding and off-grid color grinding both still run). Whatever the intended semantics of the own-shield gate (beam can't cross own bubble / no griefing from inside invulnerability), color grind is an inconsistent hole in it.

## Root Cause
Gate added to one of two grind routes; UI text written for a broader rule than implemented.

## Fix
Decide the intent: either extend the own-shield off-grid gate to the color-grind route (consistent rule), or narrow the CustomInfo text to describe what actually happens. Document the decision in this ticket.

**Resolution:** commit 542b90b (BuildId 260612.13) on `fix/v2.5.6` - the own-shield off-grid gate moved out of the autogrind branch so it covers color grind too (consistent rule chosen over narrowing the text); CustomInfo now says "Grinding limited to own grid!" which matches the actual behavior.
