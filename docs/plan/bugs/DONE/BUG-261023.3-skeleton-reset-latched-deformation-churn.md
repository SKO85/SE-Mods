# BUG-261023.3: SkeletonResetHandler re-resets every once-dented block forever and ignores the weld filters

## Status: Fixed
## Severity: Medium
## Version: v2.5.6
## Found In: REVIEW-261023.1 #3 — `Handlers/SkeletonResetHandler.cs`, `NanobotSystem.Scanning.Block.cs:246-260`, `Extensions/SlimBlockExtensions.cs:47-56`

## Description
The scan enqueues a skeleton reset for any full-integrity block with `MaxDeformation > 0.01`. The
engine caches that value (`MySlimBlock.m_cachedMaxDeformation`, refreshed only by `UpdateMaxDeformation`)
— the code's own comment says it "doesn't reset until restart". So after the first reset the block still
qualifies; it is re-queued every time the 60 s per-block cooldown expires and
`ResetBlockSkeleton(block, updateSync: true)` runs again — skeleton work plus a network sync per block, for
every block ever dented within range, for as long as the BaR runs (capped at 2 per tick ≈ 120/s).

The enqueue also skips the filters every other weld action respects: ignore colour, weld priority
(class disabled) and `WeldSkeleton` mode ("never repair existing blocks"). (Safe-zone welding is
checked by the enclosing branch — see Fix.)

## Steps to Reproduce
1. Dent 200 armor blocks (collision), weld them back to full.
2. Leave a BaR running near them; profile `SkeletonResetHandler.Process` for 5 minutes.
3. Resets continue every ~60 s per block although nothing is dented.

## Root Cause
Enqueue condition uses the latched `MaxDeformation`, and the reset path was added outside the normal
weld-target filter chain.

## Fix
Implemented (BuildId 261023.3).
- `SkeletonResetHandler.Process` (main thread) re-checks `block.HasDeformation` before resetting.
  Not deformed → the per-block 60 s cooldown is stamped and the entry is skipped
  (`skippedNotDeformed=` in the profile line), so a latched block costs one `HasDeformation` check per
  minute instead of a reset + sync. Dequeues capped at 16 per tick (`MaxDequeuesPerTick`); resets stay
  capped at 2 per tick.
- Scan enqueue (`NanobotSystem.Scanning.Block.cs`) applies the weld-target filters: not in
  `WeldSkeleton` mode, ignore colour and grind colour, `BlockWeldPriority.GetEnabled`.
- The check stays on the main thread (not in the background scan) to avoid adding skeleton reads to
  every scan of every latched block.
- Correction to the description: the safe-zone check already applied — the enclosing branch returns
  early when `!State.SafeZoneAllowsWelding`.

Files: `Handlers/SkeletonResetHandler.cs`, `NanobotSystem.Scanning.Block.cs`.

Verification: unit — `SkeletonResetHandlerTests` (3: skip + cooldown for undented blocks, 2 resets per
tick, skips don't eat the reset cap; the first and third fail on the old drain). In-game: pending —
SCN-WELD-006 (steady state `resets=0` after the first minute).
