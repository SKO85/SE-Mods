# BUG-261023.14: Companion auto-queuing under-queues: assembler output stock is subtracted twice

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-261023.1 #14 — `Utils/UtilsProductionBlock.cs:57-121` (`EnsureQueued`), `NanobotSystem.Welding.cs:1470-1487` (aggregate source subtraction)

## Description
Since BUG-260824.2 the aggregate `MissingComponents` is already net of stock in connected sources —
which include assemblers' output inventories (FEAT-011). `EnsureQueued` then subtracts the assembler's
output inventory again (plus its queue). Example: need 100, 30 sitting in the assembler output →
aggregate reports 70 → EnsureQueued queues 70 − 30 = 40 → total available 70, short by 30 until BaR pulls
the output. It converges, but slower than intended.

## Steps to Reproduce
Empty cargo, assembler with 30 SteelPlate in its output, BaR needing 100 → watch the queued amount.

## Root Cause
Two layers each subtract the same stock.

## Fix
Implemented in the companion script, not the mod.
- Why there: `EnsureQueued` is public scripting API with a documented contract ("inventory + queue
  counts as available") and the aggregate is correct for the terminal display; the double subtraction
  comes from the script feeding the net shortfall into an API that subtracts output stock again.
- `CheckAssemblerQueues` now calls `EnsureQueued(assemblers, id, missing + AssemblerOutputAmount(id))`,
  where `AssemblerOutputAmount` sums the item in the output inventories of the group's assemblers that
  are in Assembly mode (the same ones `EnsureQueued` counts). Worked through both cases: assembler
  connected to the BaR (aggregate already net of its output) and not connected (output unreachable for
  the BaR) — both now queue `need − stock − queue`. The script takes the max over BaRs (not the sum),
  so adding the output back once is right.
- Assembler blocks are resolved once per (30 s) re-init (`AssemblerBlocks`).

Verification: unit — `CompanionScriptTests` (script compiles). In-game: pending — SCN-WELD-005 step 4
variant: 30 of the needed component pre-stocked in the assembler output, queue empty → the script
queues need − 30 at once.
