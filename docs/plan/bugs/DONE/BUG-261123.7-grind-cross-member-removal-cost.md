# BUG-261123.7: Each ground block scans every cluster member's grind list (cost grows with cluster size)

## Status: Done
## Severity: Low
## Version: v2.5.7
## Found In: FEAT-261123.4 grind sub-timers (S66 / S67 / S70 detail, BuildId 261123.37)

## Description
After a block is fully ground, RemoveGrindTargetEverywhere removes it from every cluster member's list by position (a
linear scan per member). With 10-BaR clusters that is 11-15 % of ServerTryGrinding time (0.066-0.099 ms per ground
block, ~3 ms per second of grinding); with 2-BaR clusters 3 %.

## Fix
Fully dismounted blocks are removed from the grinding BaR's own list only (`RemoveGrindTarget`); the other members see
the entry as dead and drop it on their next walk (BUG-261123.3). Janitor targets that reached their Disable / Hack
threshold keep the cross-member removal (other members cannot tell they are done). An exhausted member wakes on its
retry interval or the next scan as before; removing a dead entry gave it nothing new to grind anyway.

## Scenario
SCN-GRIND-007 — ingame:S66, S67, S70 (detail: removeEverywhereMs, deadRemoved).

## Resolution
Fixed in BuildId 261123.38. Detail run S66 / S67 / S70 and `@grind` (14 scenarios incl. janitor S17 / S45, protection
S73 / S74, S112) all pass.

| | S66 before / after | S67 before / after | S70 before / after |
|---|---|---|---|
| cross-member removal per ground block | 0.066 / 0.005 ms | 0.018 / 0.004 ms | 0.099 / 0.005 ms |
| cross-member removal, share of grind time | 11 % / 0.8 % | 3 % / 0.7 % | 15 % / 0.8 % |
| grind overhead (everything but the engine grind) | 106 / 106 ms | 92 / 81 ms | 149 / 92 ms |

The removal cost is gone; part of it moves into the members' own walks (their dead-entry drop), so the net gain is
0 % (S66), -12 % (S67) and -38 % (S70) of the grind overhead. The engine grind is now 78-85 % of ServerTryGrinding.
