# BUG-260610.34: _LastSuccessfulSource pins a possibly-closed inventory indefinitely

## Status: Fixed
## Severity: Low
## Version: v2.5.6
## Found In: REVIEW-260610.1 — `NanobotSystem.Welding.cs:1192, 1019-1031`

## Description
`_LastSuccessfulSource` stores the source `IMyInventory` and is never cleared when the source list is rebuilt or the owner closes — only overwritten on the next successful pull. Until then every `PullFromSourcesOnePass` call pays a futile `ReferenceEquals` walk over the sources list, and the reference keeps a closed entity's inventory graph alive (managed memory only).

## Root Cause
No invalidation hook for the cached fast-path source.

## Fix
Clear `_LastSuccessfulSource` when `_PossibleSources` is rebuilt (scan apply) and/or when the lookup walk fails to find it in the current list.

**Resolution:** commit 6ab9c9d (BuildId 260610.23) on `fix/v2.5.6` - _LastSuccessfulSource is nulled when the locate walk fails to find it in the rebuilt source list - stops the futile walk and unpins the closed inventory graph. Build: Debug, 0 errors.
