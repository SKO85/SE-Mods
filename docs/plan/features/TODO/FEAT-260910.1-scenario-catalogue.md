# FEAT-260910.1: Scenario catalogue — every BaR feature/behaviour as a testable scenario

## Status: In Progress
## Priority: High
## Version: v2.5.6
## Summary
`docs/plan/scenarios/` catalogue: one `SCN-<AREA>-NNN` file per feature/behaviour with preconditions,
steps, expected outcome, perf envelope and a coverage field (manual | unit | ingame). It is the spec
that FEAT-260910.2 (in-game harness) and FEAT-260910.3 (unit tests) point back at.

## Motivation
Every regression so far (#141, #142, #143, BUG-260827.x) was found by players or by hand-driven
profiling. 96 fixes are queued for v2.5.6 with no way to prove they still hold. Before automating
anything we need the list of what "covered" means, readable from one index.

## Design
- Folder `docs/plan/scenarios/`: `README.md` (template + rules), `state.md` (index), `<AREA>/SCN-<AREA>-NNN-<short>.md`.
- Areas: CORE WELD GRIND COLLECT INV PRIO CLUSTER BUDGET ZONE FX TERM API CFG CHAT NET LOC.
- IDs are `SCN-<AREA>-NNN` — a deliberate exception to `<TYPE>-YYMMDD.N`: scenarios are a permanent
  catalogue, not dated events; area prefixes make coverage gaps visible per area.
- No TODO/DONE split. Coverage is a field; removed behaviour → delete the scenario.
- Tiers: 1 single BaR/grid, 2 multi-setting, 3 multi-BaR/multi-grid, 4 DS/multiplayer or perf.
- Honesty rules: `bugs/README.md` gains `## Scenario` (name the SCN added/updated or
  `no scenario: <reason>`); `features/README.md` `## Testing` lists SCN ids; a
  `REVIEW-YYMMDD.N-coverage-pass` per release walks `scenarios/state.md`.

## Files Affected
- New: `docs/plan/scenarios/README.md`, `state.md`, ~34 `SCN-*` files.
- Modified: `docs/plan/state.md` (Scenarios pointer), `docs/plan/bugs/README.md`,
  `docs/plan/features/README.md`, `CLAUDE.md` (planning section; fix stale "gitignored" note).

## Testing
Catalogue review: every `[A]`-marked scenario has a planned harness id (S01..S09), every `[U]` a planned
test name; `state.md` matches the files. Nothing runs yet — coverage is `manual` until .2/.3 land.
