# FEAT-261122.4: Test coverage plan for v2.5.7

## Status: Proposed (owner 2026-11-22: plan now, implement in v2.5.7)
## Priority: Medium
## Version: v2.5.7
## Summary
Prioritised list of unit tests and in-game harness scenarios to add next, highest player risk first. Sources:
REVIEW-261122.2 findings 3-14, the audit's other gaps (manual-only / thin / never-measured), and follow-ups from the
2026-11-22 fixes. Harness ids continue after S76 (S77+); numbers below are suggestions, assign on implementation.

## Motivation
v2.5.6 added 240 unit tests and S00-S76, but whole behaviours are still unchecked: GrindBeforeWeld, inventory sources and
push targets, cluster re-election, the network receive path, chat commands, collecting edge cases, power beyond welding.
These are exactly the areas where earlier releases broke silently (inventory full, missing components, claims).

## Plan
P = priority (1 = do first). Kind: U = unit (`tests/`), H = in-game harness (`Testing/Scenarios`).

## Implementation notes
- Inventory / work-mode / cluster scenarios reuse RigSpec extras (Assembler, Connector, CockpitSeat) and the S38
  connector docking; refinery / sorter / cryo need new `RigBlockKind`s.
- Unit tests derive from ModTestBase; the network tests need a fake `IMyMultiplayer` (MyAPIGateway.Multiplayer is
  settable).
- Every new test gets its SCN coverage token and a harness.md entry (CatalogueConsistencyTests enforces both).
