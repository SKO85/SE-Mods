# FEAT-261122.2: Option to stop BaRs grinding enemy grids that are moving or piloted

## Status: Proposed (not scheduled — owner 2026-11-22: "not for now, ticket as an option")
## Priority: Low
## Version: —
## Summary
Bring back a ModSettings switch like v1.6.1's `AllowEnemyGrindingInMotion` (default off): BaRs do not grind enemy
grids that are moving or controlled by a player, so a BaR ship cannot be used as a weapon against other ships.

## Motivation
v1.6.1 (commit 9f6be50, "Fix/configs and motion grids") had it; the v2.0.0 rewrite removed it ("Moving grid
tracking has been temporarily removed", release notes v2.0.0). Current behaviour, checked by harness S45: a BaR
grinds a pirate ship flying alongside. Servers with PvP rules may want the old protection back.

## Design (sketch)
- `SyncModSettings.AllowEnemyGrindingInMotion` (bool, default true to keep today's behaviour, or false like
  v1.6.1 — owner decision), ProtoMember + XML, `/nanobars config` entry.
- In `AsyncAddBlockIfGrindTarget`, for janitor relation Enemies (maybe Neutral): skip when the target grid moves
  (`Physics.LinearVelocity` above a small threshold) or is controlled (cockpit/remote with a pilot). Cache per grid
  for a few seconds (the v1.6.1 version used `_IsMovingOrControlledCache`) — background scan thread, read-only checks.
- Grind colour unaffected (own blocks only).

## Testing
Harness S45 split into a pair: switch on → pirate ship in flight ground; switch off → left alone (and ground once
it stops). SCN-GRIND-002.
