# FEAT-261122.1: FAQ — projections switch off when no player is near the projector

## Status: Done
## Priority: Low
## Version: v2.5.7
## Summary
Document that BaR cannot build projections while the game has switched the projection off because no player is
near the projector's grid.

## Motivation
Expected question after the 1.211 fix ("BaR builds while I'm there, stops when I log off"). It is game behaviour,
not a BaR bug, and not new: `MyProjectorBase.UpdateProjectionVisibility` sets `TierCanProject = false` when the
grid's `PlayerPresenceTier` is Tier1/Tier2 (`MyTieredUpdateSystem`). IL-identical in the May 2026 server build and
in 1.211, so it predates Warfare 3 (verified 2026-11-22). Ship welders are not tiered
(`MyFunctionalBlock.IsTieredUpdateSupported = false`), so BaR itself keeps running; only the projection is gone.

## Implementation
- FAQ entry on the docs site (Build-and-Repair-System FAQ): what happens, why, and that the build resumes when a
  player comes back in range (BUG-261122.3 makes the BaR pick it up within one scan).
- No code change. The PR #151 idea of re-triggering on a new preview-grid id is covered by the cold-start path.

## Testing
SCN-WELD-002 note only.

## Resolution
FAQ entry "My BaRs build a projection while I'm around, but stop when I log off or fly away" under Scanning &
Detection (`docs/pages/Build-and-Repair-System/FAQ/index.md`). Docs only.
