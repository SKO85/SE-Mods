# FEAT-261006.1: Korean localization via `LanguageOverride` setting (GitHub #145)

## Status: Done
## Priority: Low
## Version: v2.5.6
## Summary
Ship the Korean terminal-text dictionary contributed by najeong2 (#145) behind an opt-in mod setting,
because Space Engineers has no Korean UI language and therefore no way to select it automatically.

## Motivation
#145 attached a tested Korean translation. The attachment as a whole could not be applied: it replaced
English with Korean in place across 18 files (chat responses, HUD, state strings, info panel,
`CubeBlocks.sbc` names) and hard-forced the Korean dictionary in `Texts.cs` — a Korean-only test build,
not a localization. Verified against the game's `VRage.dll`: `MyLanguagesEnum` is
`English … ChineseChina, Japanese` — no Korean — so `Session.Config.Language` can never pick a Korean
dictionary. The dictionary itself (`TextsKorean.cs`, 102 keys, exact 1:1 with `TextsEnglish.cs`) is good.

## Design
- `Localization/TextsKorean.cs` — contributed dictionary, header credits najeong2.
- `SyncModSettings.LanguageOverride` (`ProtoMember(44)`, synced to clients): `""` = game language,
  `"ko"` = Korean. `ValidateAndClamp` folds anything else back to `""`.
- `Texts` static ctor: when the override is `"ko"` the texts are
  `LocalizationHelper.Merge(TextsEnglish.Dictionary, TextsKorean.Dictionary)` (English fallback kept);
  otherwise the existing `GetTexts(game language)` path. `GetTexts` now delegates to the new `Merge`.
- `/nanobars config set LanguageOverride none|ko` (`ConfigCommand` entry, `EnumSetting`); documented in
  `Config/general-settings.md`. Applies on world load / rejoin — `Texts` is a static class initialised
  once per session.
- Also wired: `Mod.Settings.DisableLocalization` is now honoured by `Texts` (previously only the never-set
  `Mod.DisableLocalization` static was read, so the documented XML setting was dead).
- Not taken from the submission, deliberately: hard-coded Korean chat/HUD/state/info-panel strings
  (those strings are not localised for DE/PL/RU either — making them localisable is a separate feature),
  `CubeBlocks.sbc` names (no per-language mechanism for a language the game lacks), the `Texts.cs` force,
  and the terminal action-name changes (already done on this branch by BUG-260610.37).

## Files Affected
`Localization/TextsKorean.cs` (new), `Localization/Texts.cs`, `Localization/LocalizationHelper.cs`,
`Models/SyncModSettings.cs`, `Chat/Commands/ConfigCommand.cs`, csproj, `Constants.cs` (BuildId 261006.2),
`docs/pages/Build-and-Repair-System/Config/general-settings.md`.

## Testing
Build green (BuildId 261006.2). In-game: `/nanobars config set LanguageOverride ko`, `config save`,
reload → terminal labels/tooltips/info-panel texts Korean, English fallback for any missing key;
`set LanguageOverride none` + reload → game language again; `set LanguageOverride xx` → rejected;
a client joining a `ko` server receives the override via settings sync (ProtoMember 44).
Scenarios: SCN-LOC-001 (override step added).
