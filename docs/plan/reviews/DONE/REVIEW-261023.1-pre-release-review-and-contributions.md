## Summary
Two High findings must be addressed before release: the new missing-components aggregate (the #142 fix)
is an unbudgeted, phase-aligned main-thread walk repeated by every cluster member — a credible #143-class
spike introduced by v2.5.6 itself — and projected blocks are created with their first component for free
(item duplication), as PR #148 correctly diagnosed. Five Medium findings cover a skeleton-reset churn loop,
an undocumented doubling of the weld-target cap, the collect path still trusting the detached transport
inventory, the admin priority lock being bypassable by any PB script, and the companion script's broken
info-only mode. Seven Low findings are hardening/polish. Everything else reviewed held up — the
security-relevant network paths from the June/August reviews are correctly fixed.

## Notes
Checked and found sound (no ticket): sender access check + per-(block,sender) rate limit on client
settings (#144 / BUG-260610.2); client-side `fromServer` guards; admin gate on forwarded commands
(including the harness `test` command); `PushComponents` locking; weld lock-on paths after BUG-260824.9 /
260612.19; grind dismount/mech budgets and raze-queue drain budget; friendly-damage compute-on-miss
(BUG-260824.4); transport-inventory pick verification (BUG-260827.2); `CheckLimits` NaN/negative guards and
allow-mask enforcement; lowered-limit release (BUG-261006.1); Korean `LanguageOverride` clamp/sync.

Recurring themes worth keeping in mind: (a) new main-thread work must come with a budget or time slice
and a phase offset — anything per-BaR on a fixed cadence aligns within a stagger group; (b) admin policy
flags must be enforced server-side, not only in terminal predicates; (c) the detached transport inventory
needs the verified-add pattern everywhere it is a destination.

Test coverage added alongside this review: `tests/` (FEAT-260910.3) — 86 out-of-game unit tests incl. a
ProtoBuf tag-uniqueness guard and a catalogue-honesty check; no mod code changed.
