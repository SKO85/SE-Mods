## Summary
The regression is real, confirmed and fully explained: hotfix **1.211.018** (not Warfare 3 itself) added an
undocumented survival check to `BuildInternal` — the builder's own inventory must hold one of the block's first
component. BaR keeps that component in its detached transport inventory, so nearly every projected build is
silently rejected, and BUG-120's 3-strike rule then skips the block until a power cycle (#150). PR #151 part 1
is the right fix; it needs to be merged with our BUG-261023.2 charge logic on `fix/v2.5.6` and should use the
verified inventory move. PR #151 part 2 is mostly built on a wrong premise (the asynchronous
`BuildableBlocksCount` already existed in 1.210) — one piece of it is a real but minor latent bug.
Diagnostics were added so the cause is visible in default server logs and in the profiler.

## Notes
- Why it "sometimes works": `ServerEmptyTransportInventory` parks transport leftovers in the block inventory
  between ticks and `ServerPickFromWelder` picks them back; a build only passes when a spare sits there.
  `PushComponentImmediately` makes failure near-certain.
- 1.210 consequence confirmed by the same IL: `TakeMaterialsFromBuilder` only takes from the builder inventory,
  so 1.210 built projected blocks for free — consistent with BUG-261023.2 / PR #148. With the lend, the game
  takes the component itself on both 1.210 and 1.211.018; BUG-261023.2's charge then only runs when the engine
  did not take it.
- The same hotfix added a world-limit check and an RPC sender check to `BuildInternal`. BaR already checks
  `IsWithinWorldLimits` before building; anything still failing will show as `reason=unknown` in the new log.
- Diagnostics added (BuildId 261122.1, no behaviour change): `ServerDoWeld` profile `welderCompAtBuild=`;
  throttled Error-level log "projected build left no block" with reason/inventory/`CanBuild` details;
  DebugMode panel line `ProjBuild: built= noBlock= skipped= | last=`; `ProjectorProbe` profile line
  (profiling only) for stale `BuildableBlocksCount`.
- Credit Lejangt for the root cause and PR #151 part 1 (same handling as PR #148).
